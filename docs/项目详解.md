# PIKS 项目详解

> 全局背景、数据流、技术栈、边界。权威设计见根目录 `PIKS架构设计文档.md`(v1.0,已定稿)。
> 本文只记录**架构文档之外的执行决策**,并作为开发期唯一的决策登记处。

## 一句话定位

PIKS 是 **Knowledge System,不是 Trading System**。核心价值 = "我终于能解释为什么市场发生了这件事",而不是"明天买什么"。

## 三条冻结骨架(不可违背)

1. **存储分层**:`PostgreSQL = Source of Truth` / `Markdown = Knowledge Projection` / `Obsidian = Knowledge Interface`
2. **三层模型**:`Fact ≠ Inference ≠ Belief`,禁止把 AI 推测写成事实
3. **AI 边界**:`AI → Structured Output → Schema Validation → Business Validation → Knowledge Core`,AI 不直接写库

## 数据流(最终形态)

```
新闻/公告 → Collector → raw_documents → LLM 结构化抽取
  → Schema/Business Validation → Knowledge Core(PostgreSQL)
  → Markdown Generator → git → 本地 Obsidian(阅读/学习/编辑 09-Personal)
  → 你 → Belief/Case/Mistake → (Phase3)harvest 回写 → PostgreSQL
```

## 技术栈

| 模块 | 技术 | 备注 |
|---|---|---|
| Backend | Go 1.26 | cmd/api / cmd/worker / cmd/publisher 多命令骨架 |
| Database | PostgreSQL(Docker) | 6 张 V1 核心表 |
| AI | AIProvider 接口 + 首个适配器(OpenAI 兼容,覆盖 DeepSeek/订阅源) | Provider 可替换 |
| Knowledge Format | Markdown + YAML front matter | Obsidian wikilink 双链 |
| Vault 同步 | Git | 生成的 vault 独立仓库,与代码仓库分离 |
| 部署 | Docker Compose | 本地单机 |

## 边界(明确不做)

- 自动交易 / 荐股 / 买卖信号 / 真实资金 / 高频行情
- 与 steady **领域耦合**(不共享表、不互相调用);DB 级完全隔离,独立 Postgres 实例
- V1 不做:复杂前端、Neo4j、Elasticsearch、Kubernetes、微服务、多 AI Agent、十几个数据源
