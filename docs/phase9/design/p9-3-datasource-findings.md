# P9-3 行业数据管线 —— 实测数据源结论(写码前的事实依据)

> 2026-09-16 实测 akshare 1.18.94,lab 生产网。以下每条都是**跑出来的**,不是查文档得来的。
> 用途:锁定 D-R7「估值只做横截面」的**可溯源边界**;越界的字段一律不写。

## 1. 可用的接口(实测通过)

| 接口 | 返回 | 实测 |
|---|---|---|
| `index_hist_sw(symbol="801010", period="day")` | 6456 行 × 8 列:`代码 日期 收盘 开盘 最高 最低 成交量 成交额` | 1999-12-30 → 2026-09-15,26 年 9 个月 |
| `sw_index_first_info()` | 31 行 × 7 列:`行业代码 行业名称 成份个数 静态市盈率 TTM(滚动)市盈率 市净率 静态股息率` | **31 个一级行业** ← 横截面排名的基准 = 31 |
| `sw_index_second_info()` | 131 行 × 8 列(多 `上级行业`) | 二级 |
| `sw_index_third_info()` | 335 行 × 8 列 | 三级 |
| `sw_index_third_cons(symbol="850111.SI")` | 成分股 × 18 列,含 `市盈率ttm 市净率 ROE(%) 股息率 市值 净利润增速(%) 营收增速(%)` | **仅三级有 cons**;一级/二级无 |

耗时(单次):`third_info` 1.1s / `first_info` 1.1s / `third_cons` 0.2–0.3s / `index_hist_sw` 2.7s。

## 2. 三个字段口径的**硬事实**(决定版面能写什么)

### 2.1 `index_hist_sw` 的「成交量/成交额」**不是量纲正确的成交额**

实测白酒Ⅲ(851251)指数行:`成交量=0.8147`、`成交额=45.5178`;而同日成分股合计市值 = **23629 亿**。
0.81 手 / 45.5 元的「成交额」对 2.4 万亿市值的板块显然不成立 —— 这是申万指数的**内部单位**
(很可能已是「亿股 / 亿元」,或指数化后的相对量),**无法与 A 股个股的「手 / 元」口径对齐**。

**结论**:行业研报**不写成交额/成交量的绝对值**,只写点位与由其派生的涨跌、回撤、波动。
写「成交额 45.5 亿」= 编造量纲,Number Lint 也拦不住(数字在卡片里)→ 必须靠**不采集**来杜绝。

### 2.2 成交额/成交量单位不一致是既存事实,不是本次引入

`akshare_provider.py:70` 把腾讯的 volume `//100` 转「手」、turnover `×100` 转百分比 —— 个股侧
单位已归一。行业侧没有对应归一规则,故**不采集**是唯一诚实做法。

### 2.3 层级归属必须**查表**,不能推

- `801010` = **农林牧渔**(104 只),不是「食品饮料」。代码↔名称**唯一来源是 `sw_index_*_info`**。
- 二级/三级**不含一级代码**:`sw_index_second_info` 里查 `801010` 无结果 → 判定层级必须**逐级查表**。
- 三级↔一级映射需**两跳**:`third.上级行业`(二级名) → `second.上级行业`(一级名)。实测
  `基础化工` L3 成份个数合计 412 == L1 挂牌 412(电力设备 379==379、机械设备 542==542)→
  **两跳映射正确**,可作 ULT 校验。

### 2.4 三级覆盖不全,横截面成分基准用**一级 31 个**

实测个股 600519(贵州茅台)所属三级行业 = **白酒Ⅲ 851251**(经 `sw_index_third_cons("851251.SI")`
实测含「贵州茅台」)。但三级共 335 个,`index_hist_sw` 对 851251 只有 **1148 行(2021-12-13 起)**
—— 新设/重分类的三级码历史短,「1999 年以来分位」对它们**不可得**。故:
**二级/三级主体的历史分位须以 `index_hist_sw` 实际返回的首日为界如实标注**,不得写「1999 年以来」。

### 2.5 估值只有**当期快照**,无历史序列(D-R7 的实测根据)

`sw_index_*_info` 的 PE/PB/股息率 = 当期快照一列。`index_value_hist_funddb` 在本版本 akshare
**不存在**;`stock_index_pe_lg` 只覆盖宽基。→ **「估值历史分位」不可算**。可算的是:
- **横截面排名**:31 个一级行业内 TTM PE 的位次(基准 = 31)
- **点位历史分位**:由 `index_hist_sw` 长序列算(与估值无关)

## 3. 由此确定的采集/版面边界

| 章节 | 可写 | **禁止**(数据源不支持 = 写了即编造) |
|---|---|---|
| 行业行情 | 点位、区间涨跌、**点位历史分位**、最大回撤、年化波动 | 成交额/成交量绝对值(量纲不明,见 2.1) |
| 估值定位 | 当期 PE(TTM)/PB/股息率 + **31 行业内横截面排名** | 「估值处于近 N 年 X% 分位」 |
| 成分结构 | 一级行业成份个数;三级行业成分股 ROE/净利增速/营收增速的**中位与四分位** | 一级行业逐股财务(无一级 cons 接口) |

## 4. 若本次只做一级(L1)

申万**只有一级**(31 个)有完整的「历史 + 估值 + 成分数」三件套。二级/三级虽 `index_hist_sw`
可用,但估值快照与成分结构缺 cons 接口(一级无 cons;二级无任何 cons)——
**分级要各自诚实标注能写什么**,不能假装一致。

## 5. 实现期补记(2026-09-16,管线打通后)

### 5.1 官网限流是**常态**,不是偶发

实测 `www.swsresearch.com` 被频繁请求后会进入长时间的 **HTTP 508**:
`sw_index_first_info` 抛 `AttributeError: 'NoneType' object has no attribute 'find_all'`
(akshare 拿到的 HTML 里没有目标表格),`sw_index_third_cons` 抛 `ValueError: No tables found`。
`index_hist_sw` 走**另一个 host**,不受影响(仍返回 6456 行)。

→ 后果与对策:
- **行业表必须在线优先、磁盘兜底**:这三张表是当期快照,磁盘缓存永久生效 = 把估值
  冻死在首次抓取那天。故顺序为「进程内 → 在线(重试) → 磁盘」。
- **成分聚合必须熔断**:一级/二级成分是把**上百个**三级 cons 聚合出来的,官网 508 时
  每次卡 ~5s,逐个硬试就是分钟级空转。连续失败 3 次即停止再试,余下记空。
- 官网不可用时的**诚实输出**:成分结构章节写「_成分股明细暂不可得_」+ 挂牌成份数,
  估值章节仍可用(估值来自 info 表,非 cons 接口)。

### 5.2 指标卡形状:行业**没有** price/volume 节

`json_report.generate_json` 原先无条件 `asdict(price_metrics)`;行业 profile 不含
`market`/`volume` section → 两者为 `None` → `asdict(None)` 抛
`TypeError: asdict() should be called on dataclass instances`。已改为**省键**
(缺席应表现为「没有」,而非一个会被遍历到的空值)。

⚠️ **连带坑**:合成提示的指标摘要是**单层**过滤(`synthesis.py` 只收
`isinstance(v, (int,float,str))`),嵌套一层的 `price`/`valuation_rank` 会被**整体丢弃**
→ LLM 看不到任何数字(实测只剩 `declared_count`/`constituent_count`)。故行业指标卡
**平铺到 `industry_index` 顶层**(嵌套块原样保留,契约不变)。个股各 section 的关键数字
本就平铺,不受影响。

### 5.3 质量门原先按个股假设写死

`quality_gate.py` 有三处只认个股:
- `SECTION_TO_KEY` / `SECTION_FOR_SECTION` 不认识 `industry_index|industry_valuation|industry_structure`
  → 覆盖率 25%、Evidence 缺失
- `time_boundary` 只读 `json_report["price"]["period_days"]`;行业无 `price` 节 → period_days ✗

已按主体补齐映射,`time_boundary` 改为「industry_index.price 兜底」。
行业 Evidence 由新增的 `add_industry_evidence()` 登记(不能复用 `run_analysis` ——
它会顺手对指数跑 `analyze_volume`,产出无口径的「换手率」)。
