# PIKS 项目详解

> 全局背景、数据流、技术栈、边界。权威设计见根目录 `PIKS架构设计文档.md`(v1.0,已定稿;顶部含「现状偏差」注记,记录落地演进)。
> 本文只记录**架构文档之外的执行决策**,并作为开发期唯一的决策登记处。

## 一句话定位

PIKS 是 **Knowledge System,不是 Trading System**。核心价值 = "我终于能解释为什么市场发生了这件事",而不是"明天买什么"。

## 三条冻结骨架(不可违背)

1. **存储分层**:`PostgreSQL = Source of Truth`;界面层在迭代 5 由「Markdown 投影 + Obsidian」演进为 **Web(PG 直渲)**,Obsidian/GitHub 于 5-2 下线(`PIKS-Vault/` 仅存档)。原 v1.0 蓝图的 `Markdown = Knowledge Projection` / `Obsidian = Knowledge Interface` 已被 `docs/phase2/design/web-app.md` 取代。
2. **三层模型**:`Fact ≠ Inference ≠ Belief`,禁止把 AI 推测写成事实
3. **AI 边界**:`AI → Structured Output → Schema Validation → Business Validation → Knowledge Core`,AI 不直接写库

## 数据流(最终形态)

```
新闻/公告 → Collector → raw_documents → LLM 结构化抽取
  → Schema/Business Validation → Knowledge Core(PostgreSQL)
  → Web 直渲(看板/事件/实体/图谱/复盘/对账/周报/交易/AI 对话)
  → 你(Web 内编辑 personal_notes:Belief/Case/Mistake/我的理解 + 交易截图录入)
  → 落回 PostgreSQL(权威源唯一,无 vault/git 中间层)
```

## 技术栈

| 模块 | 技术 | 备注 |
|---|---|---|
| Backend | Go 1.26 | 9 个管线命令 + `cmd/web` 平台 + `probe` 探针 |
| Database | PostgreSQL(Docker) | 唯一 Source of Truth;11 个前向迁移(0001~0011) |
| AI | AIProvider 接口 + OpenAI 兼容适配器(覆盖 DeepSeek/订阅源) | 配置存 `app_config` 表,模型分层 extract/reasoning/vision,预算护栏 |
| Interface | Web(Go html/template + 原生 SVG 图谱) | PG 直渲,Obsidian/vault 已下线(存档) |
| 部署 | Docker Compose | dev 单机 + 生产 lab(postgres + web 常驻 + tools profile) |

## 边界(明确不做)

- 自动交易 / 荐股 / 买卖信号 / 真实资金 / 高频行情;交易功能只做「记录 + 解读 + 诊断」,不连券商、不下单、不做信号
- 与 steady **领域耦合**(不共享表、不互相调用);DB 级完全隔离,独立 Postgres 实例
- 已做 Web 平台(Go 服务端渲染);仍不做:SPA 框架、Neo4j、Elasticsearch、Kubernetes、微服务、多 AI Agent、十几个数据源
