## 已知权衡与说明(数据诚实)

1. **扩展召回引入低权重噪音**:通用扩展词(如「新能源」「电池」)的 2/3-gram 会命中无关实体/事件(实测「宁德时代」扩展后出现顺钠股份等)。因扩展词 weight=0.5 + 排序,真命中稳居 top;LLM 有「只引用真实相关」约束 + `extractRefs` 只收录 LLM 实际引用的 id,噪音不会变成假引用。个人系统可接受,如需更精确可后续将扩展词改为整短语匹配(牺牲部分召回)。
2. **`merged` 事件被既有状态过滤排除**:检索 SQL `status IN ('extracted','verified','published')` 不含 `merged`(5-3 已有行为,非本迭代引入)。实测 `35a9d3f5`(标题含「降准」)因 status=merged 未参与检索——需确认 `merged` 是否应纳入 grounding,列为独立质量项。
3. **dev 环境准备**:dev 库 app_config 已指向 Zen(镜像 lab 做法),供 /chat 与扩展 smoke test;生产 app_config 未动。
4. **扩展调用失败自动降级**,成本为每次提问 +1 次 extract 档短调用(实测单次 ~3-6s 含冷启动),远小于回答本身;日预算护栏未接入(初版不做,如需后续接)。
