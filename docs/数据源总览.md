> **本文是 PIKS 全部取数链路的现状清单——以代码为准。**
> 核对:2026-09-21(dev `3a0bb62`;C 层提频为 dev-only,见 `docs/phase11/design/flash-cadence.md`)。架构全貌见 `docs/架构总览.md`,数据源扩展计划见 `research/docs/plan-data-source-integration.md`。

## 2. 数据种类 → 来源 → 代码 → 频率

### 2.1 日管线采集(有外网)

| 数据 | 来源 | 代码落点 | 频率 |
|---|---|---|---|
| **快讯** `flashes` | **6 个独立机构源**(见 §2.1.1) | `internal/collector/{dongcai,jin10,cls,sina,ths,futu}.go`;入口 `cmd/collector -driver news`(常驻)/ `-driver all`(日管线) | **盘中每 3 分钟**(交易日 09:15–15:05 常驻循环)+ 每交易日 1 次 16:10 后补齐 |
| **公告** `announcements` | **巨潮资讯网**(见 §2.1.2) | `internal/collector/cninfo_announce.go`;入口 `cmd/collector -driver cninfo-announce` | 每交易日 1 次,16:10 后 |
| **涨停/炸板/跌停池** `ladder` | 东财 `push2ex.eastmoney.com/getTopicZTPool` / `getTopicZBPool` / `getTopicDTPool` | `internal/collector/quotemarket.go:63-67`(端点)、`:118-180`(Fetch 聚合) | 每交易日 1 次,非交易日自动跳过 |
| **指数 / 成交额 / 涨跌家数** | 东财 `push2.eastmoney.com/api/qt/stock/get`(成交额、家数端点**持续被 WAF 挡**) | `quotemarket.go:246`(指数)、`:260`(家数)、`:280`(成交额)、`:297-330`(`getJSON` 重试退避) | 同上;取不到如实记 `pending` |

**落库**:快讯 → `sources`(**每机构一行,`name` = 机构名**;issue #43 前是任务名 `news-flash`) → `raw_documents`(去重见下;**`url` 有落**;上游原始字段落 **`extra` JSONB**,见 §2.1.1);
公告 → `sources`(机构名 `巨潮资讯`,**`source_type='announcement'`**) → `raw_documents`(同表;`status='collected'`,见 §2.1.2);
涨停池/指数 → `observations`(12 个指标,`cmd/quote-collector/main.go:74-118`;指标字典 `internal/marketstate/marketstate.go:14-28`)。

> **`raw_documents` 去重键**(迁移 0016,issue #50):按源是否带稳定上游标识分派 ——
> `external_id IS NULL`(如 file 保底驱动)按 `UNIQUE(source_id, content_hash)`;
> `external_id` 非空(快讯各源 + 公告)按 `UNIQUE(source_id, external_id, content_hash)`。
> 两条均为 **partial unique index**,故插入侧用**无目标**的 `ON CONFLICT DO NOTHING`。
> 起因:公告 `content` 是标题占位(正文不采集),而**公告标题由交易所模板生成、会重名** ——
> 实测 2026-09-17 东财 1377 行只有 1375 个不同标题,按标题去重会**静默丢 2 条**。

> **`raw_documents.status` 取值**:`raw`(待 LLM 抽取,快讯)/ `processed`(已抽取)/ `failed`(抽取失败)/
> **`collected`(已采集、无需抽取 —— 公告等原始事件源)**。`collected` 是公告**不进 LLM** 的关键:
> `worker` 只取 `status='raw'`,reconcile 的 `processed_no_event` 只看 `status='processed'`,两者天然都不碰它。

**健康**(issue #68 C 层改口径):**单源失败不阻断其余源**(`-driver all`/`news` 逐源记账失败,全部失败才退出码非零)。瞬时故障由 **per-host 熔断**承担(连续 4 次失败开路 60s,时间盒 + 自愈,见下)——**不再**按单轮 3 连败自动 `PauseSource`:3 分钟轮询下那样会 3 分钟就停一个源,且 `PauseSource` 写了 `status` 后**无人读取**(采集照旧轮询),坏到两头。现 collector **真正尊重 `sources.status='paused'`**:人工暂停的源**跳过**(记 `task_runs` status=`skipped`),与 `ReconSilentSources` 已排除 paused 同口径。

### 2.1.1 事件类多源(issue #43 T1,2026-09-20 落地)

事件类(主观、易漏报、各家措辞各异)须 ≥3 **独立机构**交叉验证;**同机构不同端点不算独立源**
(Go 东财 `getFastNewsZhibo` 与 akshare `stock_info_global_em` 同为东财)。现接 **6 个**:

| 机构 | 驱动 | 端点 | 原文 URL | 上游独有字段(落 `extra`) |
|---|---|---|---|---|
| 东方财富 | `dongcai` | `np-weblist.eastmoney.com/.../getFastNewsZhibo`(游标翻页) | `finance.eastmoney.com/a/{code}.html`(拼) | stockList / comment / share |
| 金十数据 | `jin10` | `flash-api.jin10.com/get_flash_list`(**纯 HTTP,需 `x-app-id`/`x-version`**) | ⚠️ **无**(detail 为 hash 路由,GET 404;**如实留空不造假**);有 `source_link` 时用它 | `important`(重要度)/`source`(一级源)/`source_link`/tags/channel |
| 财联社 | `cls` | `www.cls.cn/v1/roll/get_roll_list`(**纯 HTTP,需签名**) | `shareurl` | **`reading_num`(阅读数)**/`level`(A/B/C)/`confirmed`/stock_list/subjects |
| 新浪财经 | `sina` | `zhibo.sina.com.cn/api/zhibo/feed`(纯 HTTP) | `docurl` + `ext.docurl` | `like_nums`/tag/ext |
| 同花顺 | `ths` | `news.10jqka.com.cn/tapp/news/push/stock/`(纯 HTTP) | `url` | `tagInfo`(主题+相关度)/stock/color/nature |
| 富途资讯 | `futu` | `news.futunn.com/news-site-api/main/get-flash-list`(纯 HTTP) | `detailUrl` | `quote`(关联个股+行情)/relatedStocks/level |

> **为什么 6 个源全部自建纯 HTTP 驱动(含 akshare 本可用的同花顺/富途)**:akshare 只把部分列塞进
> DataFrame,**上游原始字段被切掉**(实测:财联社 `shareurl`/`reading_num`、新浪 `docurl`、央视文章 URL
> 上游都有而 akshare 输出没有;同花顺 `tagInfo`、富途 `quote` 同样被丢)。这些热度/分级/溯源是**时序信号**,
> 今天不留三个月后补不回来(接口只回最近 20–50 条),故 raw 层原样存上游原始 JSON 到 `extra`。

### 2.1.2 公告源:巨潮资讯网(issue #50 T4,2026-09-21 落地)

公告是**官方披露**(交易所/上市公司原文),属独立机构源,补上事件类「公告仍单源」的缺口。
接 **1 个机构**:**巨潮资讯网**(证监会指定信息披露网站)。

| 机构 | 驱动 | 端点 | 原文 URL | 上游独有字段(落 `extra`) |
|---|---|---|---|---|
| 巨潮资讯网 | `cninfo-announce` | `POST www.cninfo.com.cn/new/hisAnnouncement/query` | `static.cninfo.com.cn/{adjunctUrl}`(**原始 PDF**) | announcementId / pageColumn / announcementType / columnId / adjunct* |

**实测参数与约束(2026-09-21,勿凭想象改)**:

- ⚠️ **必须 POST**:同参数 GET 实测返回 **500 HTML 页**;故 `http.go` 新增了 `postFormJSON`
  (复用同一套限频/退避;`once` 统一了 GET/POST,避免两份退避逻辑漂移)。
- ⚠️ **scope = `column=szse` + `plate=szsh`**(单日实测 `totalAnnouncement` 2026-09-17):
  - `column=szse&plate=szsh` → **1184** ← 采用
  - `column=&plate=` → 1945(多出的 761 条是基金/债券/港股等,`pageColumn=HKZB`)
  - `column=szse&plate=sz|sh|bj` → 625 / 476 / 83(**三者相加=1184**,故 `szsh` 即深+沪+京 A股)
  - **`column=szse` 是「仅股票」过滤器,不是「深市」** —— 去掉它会混入 761 条非个股公告
- ⚠️ **`pageSize` 上限 30**(请求 50/100 均只回 30)。单日 1184 条 = **40 页**,`minGap=1s` ≈ 40s/日。
- **只存标题 + 外链,不存正文**:上游 `announcementContent` 实测恒为空(正文只在 PDF 里)。
- ⚠️ `announcementType` 是**不可解数字码**(如 `01010503||010112||010115||011705`),
  `announcementTypeName` 实测为 null,字典端点不可得 → `extra` **原样留存、不猜测含义**。

> **为什么是巨潮而不是东财**(用户定夺):两者都可行,但巨潮的 `adjunctUrl` 指向**原始 PDF**
> (`200 / application/pdf`,实测 204KB),是可直接引用的法定披露原文;东财信息页是二次呈现。
> 东财侧的公告通道(`research/src/providers/announcement/`,走 akshare)是**研报按需**取数,
> 与本节日管线采集**互不影响**,不做合并。

> ⚠️ **不抓公告正文的原因(实测)**:东财 `np-cnotice-stock` 正文接口对连续/复用连接
> **直接 RST**(300 连发 209 失败;连接复用 60/60 `Connection reset by peer`),与 §quote 侧
> 记录的 push2 IP 级限流同源;巨潮正文则只在 PDF 里。故统一**只存标题 + 原文外链**,
> 存储 ~0.23 GB/年(实测 ~1.0 MB/日),「看原文」由外链满足。

> **公告不进 LLM**:`status='collected'`(见 §2.1 落库说明),worker 只取 `status='raw'`,
> 故公告**零 token 消耗**、也**不报对账异常**。前端在消息页第三个 tab「公告」独立呈现
> (`GET /api/v1/announcements`);快讯投影已显式排除 `source_type='announcement'`,两者不混。

> ⚠️ **财联社签名算法**(实测破解,`internal/collector/cls.go`):`sign = md5( sha1( 参数按 key 升序拼 "k=v&k=v" ) )`
> —— 两层哈希均取 hex 小写,先 sha1 后 md5,**且必须排序**;只做一层或不排序均被拒(`errno:10012`)。
> 另有请求头要求 `Referer: https://www.cls.cn/`。

**限频 / 退避**(两层,issue #68 C 层补齐第二层):

1. **per-source**(`httpSource` 既有):同源请求最小间隔 **2s**,5xx/网络错误指数退避
   (200ms→400ms→800ms,封顶 2s)最多 **3** 次;4xx 视为确定性失败不重试(`internal/collector/http.go`)。
2. **per-host**(C 层新增,`internal/collector/limiter.go`):提频到盘中 3 分钟后的**硬前置**。
   同源 `minGap` 只约束「同一源相邻请求」,对「**同一 host 的突发**」(分页 + 退避重试叠加)无约束。
   三条护栏(per-host、进程内共享):

   - **令牌桶** —— 平均速率 + 突发上限(**2 req/s**,突发 **3**),请求前 `wait(ctx)`;
   - **空响应哨兵** —— **连续 3 次**「请求成功但 0 条」视为被上游**静默限流** → 该 host 有效速率
     **×1/2**(封顶 ×1/8);出现非空即复位。信号由驱动层 `Fetch` 出口喂入(`observeFetch`);
   - **熔断** —— **连续 4 次**失败 → 开路 **60s**,期间**直接失败、不发网络 I/O**;
     冷却后半开探一次,成功闭合、失败续开。

   ⚠️ **哨兵与熔断靠跨轮累积**,故护栏要**跨轮生效、采集必须常驻进程**(`-interval`)——
   一次性进程每轮状态归零,两条护栏形同虚设。这就是 `collector` 以常驻服务运行而非
   cron 每 3 分钟拉起的原因(见 §3)。实证依据:东财 push2 频繁请求回 **SSL RST(IP 级限流)**、
   东财正文接口 300 连发 **209 失败**、申万频繁请求回 **HTTP 508** —— 免费源无 SLA,护栏是不重演限流的前提。

## 3. 定时任务

定义处:`scripts/setup.sh:33-36`(部署时幂等追加到 lab `rguo@192.168.0.202`)。

```
*/15 * * * *  /home/rguo/piks/scripts/pipeline.sh   >> logs/cron.log 2>&1
59 23 * * *   /home/rguo/piks/scripts/backup.sh     >> logs/cron.log 2>&1
```

| 任务 | cron 层 | 实际频率 | 内容 |
|---|---|---|---|
| `scripts/pipeline.sh` | 每 15 分钟 | **每交易日 1 次**(16:10 后) | 9 步日管线 |
| `scripts/backup.sh` | 每天 23:59 | 每天 | `pg_dump -Fc`,保留 14 天 |
| **`collector` 常驻服务** | **无 cron** | **盘中每 3 分钟**(交易日 09:15–15:05) | 6 快讯源采集(issue #68 C 层) |

**盘中常驻采集**(issue #68 C 层)——**不走 cron**,而是 compose 常驻服务:

```yaml
collector:
  image: piks-tools:latest            # ⚠️ 复用 tools 镜像 → 仍是四镜像
  command: ["./bin/collector", "-driver", "news", "-interval", "3m"]
  restart: unless-stopped
```

- 进程内 ticker 每 3 分钟跑一轮 6 快讯源;`-session 09:15-15:05` + 工作日闸,
  时段外/周末**静默跳过、不产生请求**;`signal.NotifyContext` 收 SIGTERM/SIGINT 优雅退出。
- **为什么常驻而非 cron 每 3 分钟拉起**:反封禁护栏里的**空响应哨兵与熔断靠跨轮累积**
  (连续 N 次才触发);`tools` 容器无可写卷 → 一次性进程每轮状态归零,**两条护栏形同虚设**,
  且一天产生 ~4000 个容器。常驻把状态留内存,护栏才真正生效(见 §2.1 限频/退避)。
- **与日管线的关系**:两者幂等 + 迁移 `0016` 去重,**重复无害**。日管线 16:10 的
  `collector -driver all` 保留,兜住收盘后补齐;公告(`cninfo-announce`)只在日管线跑一次
  (单日 ~1200 条/40 页,不进盘中高频循环)。

**管线闸门**(`scripts/pipeline.sh:9-24`):

1. 日期锚取 GitHub `curl -sI https://api.github.com` 的 **`Date` 响应头**(免疫宿主机时钟漂移),取不到回退系统时钟并打 WARN;
2. 周末(`DOW>=6`)跳过;
3. 北京时间 < 16:10 跳过;
4. `logs/pipeline-$TODAY.done` 已存在跳过(防重跑);
5. 任一步失败 → **记录不阻断**。

**日管线步骤**(`scripts/pipeline.sh`),每步 `docker compose run --rm -T tools ./bin/<cmd>`:

```
migrate → collector -driver all(6 机构源) → collector -driver cninfo-announce(巨潮公告)
→ worker -limit 800 → cluster
→ quote-collector -date $TODAY → entity-build → market-state -date $TODAY
→ daily-review -date $TODAY → reconcile -date $TODAY
```

> ⚠️ `worker -limit` 已由 **300 抬到 800**(issue #68 C 层):盘中 3 分钟 × ~5.5h ≈ 110 轮,
> 日入库量比「每交易日 1 次」翻倍,原 300 会恒追不上、raw 积压。token 护栏仍是 `ai_daily_token_budget`。

> ⚠️ `scripts/health.sh`(管线完整性自检)注释写「可挂 cron」,但**实际未装进 crontab**,只能手跑。
> **日管线**调度器代码层**无**(无 cron 库 / 无 systemd timer);任务记账走 PG `task_runs` 表。
> **盘中采集**的调度器 = `cmd/collector` 的**进程内 ticker**(`-interval`),不依赖宿主机 cron。
