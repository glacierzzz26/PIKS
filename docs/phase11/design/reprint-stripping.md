# 剥转载:转载 ≠ 独立源(issue #83 分期 P-1)

> 状态:**已实现(dev-only)** · 日期:2026-09-23 · 落地:issue **#83** 分期 **P-1**
> 语义边界、阈值校准、残余上限就地实测,全文以 **lab 生产库真实语料** 为准。
> **零 schema / 零迁移 / 零管线步骤** —— 全部在**读路径**派生。

## 1. 问题:转载把「几家在报」刷高

PIKS 的印证度判定(单一来源 / 多家印证 / 广泛报道)整个建立在**机构数**这个客观计数上:
「有几家机构报道了这件事」。但 `raw_documents` 的去重键含 `source_id`(迁移 `0016` 的两条
partial unique index),**同一篇通稿被两家原样转载会落两行**;`store.ListClusterSources`
按机构名去重(`internal/store/events.go`),于是**转载把计数刷高**。

举例(实测):「卡塔尔能源首席执行官:…」三条近逐字正文,来自金十 / 新浪 / 富途 ——
机构数 3 ⇒ 看似「广泛报道」,实际是**同一篇稿被转了三道**,独立来源 **1**。

> 直接后果:计数不实 → 三级分级全废。这是 issue #83「事件管线与展示」的**根因层**,
> 与其余各期解耦,故单列 **P-1** 起步。

## 2. 语义边界:转载 ≠ 同事件(最要紧的一条)

两者**绝不能**混用同一把尺子:

| | **转载**(本篇 P-1) | **同事件**(已有,cluster 负责) |
|---|---|---|
| 定义 | 同一篇稿被**原样/近逐字**转发 | 不同机构**各自改写**报道同一件事 |
| 判据 | **正文**近逐字(Jaccard 高分区) | 标题归一化 + 语义(cluster 三关 @0.7) |
| 处理 | 不计入**独立来源数**(并为一源) | 聚成同一簇 |

两条实测反例,决定了实现形态:

1. **不得用标题指纹判转载**。同一事件的标题在多源间**天然收敛** ——
   东财「【芯源微:初步确定股东询价转让价格为320.97元/股】」与东财裸标题
   「芯源微:初步确定股东询价转让价格为320.97元/股」在 `NormalizeTitle` 后**完全相同**。
   用标题高相似度判转载,会把「一家转载」的帽子扣到**两家独立报道**头上,
   几乎所有簇塌成「单一来源」,与分级目标背道而驰。
2. **不得复用 `NormalizeTitle`**。它内含 `stripBracketWrap`,对「【标题】正文」会
   **丢掉正文、只留标题** —— 于是「裸标题」(东财)与「【同标题】+长正文」(金十)归一化后
   **同为标题串、J=1.000**,被误判成转载(实测 **156 对**如此)。同理它也把「短标题 vs 全文」
   这类**真实改写**抬到 1.0。

⇒ 指纹取 **content 原文**(去电头/HTML 标签后),**不**抽【】;归一化 `NormalizeReprintContent`
与 `NormalizeTitle` **刻意分开**(后者抽标题对**聚类**是对的,对**剥转载**恰好有害)。

## 3. 校准(证据,非拍脑袋)

**语料**:lab 生产库 `piks-postgres`,2026-09-20~21,`source_type='news'`,
按 `events.cluster_id` 分组取**簇内跨机构**两两对 —— **398 个多机构簇 / 1369 篇成员 /
2735 个跨机构对**。复刻 Go 的归一化逻辑在 Python 侧算 `Bigrams`+`Jaccard`(取证明细见 §6)。

### 3.1 分布(强双峰)

正文指纹(含电头剥离),2735 对:

| 区间 | 对数 | 占比 | 人工核对结论 |
|---|---|---|---|
| 0.70–0.75 | 30 | 1.1% | 改写(短标题 vs 全文 / 换措辞) |
| 0.75–0.80 | 11 | 0.4% | 改写 |
| **0.80–0.85** | **28** | 1.0% | **近逐字真转载**(电头/「市场消息:」/尾部括注差异) |
| **0.85–0.90** | **30** | 1.1% | **近逐字真转载**(0.84~0.88 逐条核对**全部为真**) |
| **0.90–0.95** | **28** | 1.0% | **真转载**(措辞极近,仅电头或一两个虚词之差) |
| **0.95–1.00** | **72** | 2.6% | **逐字相同**(归一化后完全一致) |

p75 = 0.333、p90 = 1.000 —— 0.80 与 1.00 之间是清晰边界。
**门控取值 `0.85`**:落在「下沿 0.80 全是真转载」的**内侧**,把「短标题 vs 全文」
(J≈0.73~0.79)这类**改写**挡在外面。**宁漏勿误** —— 误判会把两家独立报道并成一源、
直接**压低**印证度,是更坏的错。

### 3.2 电头剥离是必要的

实测 **18.3%(251/1369)** 的成员行带频道电头(「财联社9月21日电，」「金十数据9月21日讯，」),
**含【标题】后紧跟**的形态(「【标普500指数涨幅扩大至1%】财联社9月21日电，…」)。
不剥电头:≥0.85 真转载 **397** 对;剥电头后 **453** 对(+56),
而**混合区(0.75~0.85)对数不变** —— 即电头剥离**只把真转载抬过门控,不把改写抬过**。
故实现里做电头剥离(正则 `reprintDatelineRe`,保留前导【标题】、只去时间戳)。
HTML 标签剥离(`<b>…</b>`)同理:剥后 J 由 0.87 抬到 1.0。

### 3.3 效果量化(@0.85,含电头剥离)

| 指标 | 数值 |
|---|---|
| 多机构簇数 | 398 |
| 独立来源数 < 机构数的簇 | **199(50.0%)** |
| 由「≥2 家」跌到「恰好 1 个独立来源」的簇 | **159(39.9%)** |

即:**近四成**原本显示「多家印证」的簇,实际只有**一个**独立来源(其余全是转载)。

## 4. 实现(读路径派生,零 schema)

与 `cluster_sources` / `source_count` / `event_conflicts` **同一既有范式** ——
`is_reprint`/`canonical_id` 列按 issue 原文归 **P-2 迁移 8 项**,不在本次。
（P-2 已落地:经复核 `is_reprint` **不落**(本读路径即真源),只新增 `origin_kind` /
`event_clusters.canonical_event_id` / `canonical_id` / `human_verdict` 四列,见 `event-pipeline-p2.md`。）

| 文件 | 改动 |
|---|---|
| `internal/cluster/reprint.go`(新) | 纯函数:正文指纹 / 转载分组 / 独立计数 / 逐来源标记 |
| `internal/store/events.go` | `ListClusterSources` 的 SELECT **增出 `rd.content`**;`ClusterSource` 增 `Content` |
| `internal/web/api_v1.go` | `apiClusterSource` 增 `reprint`;`apiEventItem` 增 `independent_count`;`toEventItem` 对接 |
| `frontend/src/...` | 三级标签改读 `independent_count`;来源区逐条标「(转载)」 |

- **`independent_count` 与 `source_count` 并存**:后者是「**机构数**」这个客观计数
  (`api_v1.go` 有明文注释),**不改它**破坏既有语义;前者是新的「独立来源数」。
  印证度三级判定**改看前者**。
- **`toEventItem`** 对簇内各机构**代表正文**跑 `cluster.GroupReprints`,回填
  `IndependentCount`(组数)与每个来源的 `Reprint` 布尔。未聚类事件 = 1。
- **空正文不参与合并**(各自成组)—— 不因「没内容」把两家捏成一个来源。

## 5. 已知残余精度上限(如实登记,阈值调优无法消除)

- **改写型转载漏判**:各家**改写**同一通稿(换措辞保事实)时指纹漏判 → 仍会**高估**印证度。
  0.75~0.85 区间里的真转载即此边界的实测样本,不为此下调门控。
- **电头形态未穷举**:`reprintDatelineRe` 覆盖「[非空白≤12字]N月N日电/讯，」这一族;
  更长的机构前缀或非「电/讯」措辞会漏。宁可漏(仍算独立来源)不误合。
- **只判「回和」不判「同源」**:两家各自独立采编但恰好措辞撞车(极短快讯尤甚),
  会被并成一源。短稿样本少,未为此加长度门。

## 6. 取证脚本(可复现)

校准在 lab 库上执行,步骤:

1. 取近两日成员行:
   `SELECT e.cluster_id, s.name AS source, rd.content FROM events e JOIN sources s … WHERE e.source_type='news'`,
   按 `cluster_id` 分组,仅保留 ≥2 不同机构的簇。
2. 取簇内**跨机构**两两对,复刻 `NormalizeReprintContent`(去电头 + 去 HTML + 折叠空白标点 + 小写
   + 留汉字/字母数字)→ `Bigrams` → `Jaccard`。
3. 按 §3.1 打分布,并对 0.80~0.88 区间**逐条人工核对**;对 0.75~0.80 核对确认是改写。

对齐 Go 的回归断言:`internal/cluster/reprint_test.go` 的真转载/改写用例**逐字取自本语料**
(括号内为实测 Jaccard),防日后有人为凑数下调阈值。
