## 0. 一句话定位

PIKS 是 **Knowledge System,不是 Trading System**。

核心价值 = 「**我终于能解释为什么市场发生了这件事**」,而不是「明天买什么」。

形态:A 股个人投研平台。把公开市场信息(快讯、涨停池、行情、龙虎榜、财务、行业指数、宏观指标)
自动加工为**结构化事件与实体**,沉淀进 PostgreSQL;再经 React 界面完成
**研究 → 决策 → 持仓 → 复盘**的个人闭环。

## 1. 三条冻结骨架(不可违背)

贯穿全部代码的三条硬约束。任何新功能都不得绕过。

| # | 骨架 | 在代码中的落点 |
|---|---|---|
| 1 | **PostgreSQL = Source of Truth** | 20 个前向迁移(0001~0020)建 23 张表 + 运行时 `schema_migrations` 记账表;Markdown/Obsidian 投影层已于迭代 5-2 下线,`PIKS-Vault/` 仅存档 |
| 2 | **Fact ≠ Inference ≠ Belief** | 研报三域标记 `fact 数据 / calc 计算 / opinion 研判`(`lib/constants.ts` `DOMAIN_LABEL`);`metrics` 是**数字唯一源(Fact)**,LLM 只写 `opinion` |
| 3 | **AI 不直接写库** | `AI → Structured Output → Schema Validation → Business Validation → Knowledge Core`。AI 输出先落 `raw_documents`/task 中间态,经校验才进知识核心;research 侧另有 Number Lint + Quality Gate 两道机检 |

> 骨架 3 的具体体现:深研 LLM **从不触碰数值**——所有数字由 Python 确定性计算出,LLM 只写三段定性叙述,
> 写完后由 Number Lint 反向扫描报告正文,把「不是程序算出来的数字」全部报为 issue。

## 2. 系统全景

PIKS 是**同仓三运行时、四镜像交付**的个人系统(2026-09-20 容器拆分,issue #47)。

```
                    ┌───────────── piks-gateway(nginx:alpine)──────────────┐
   浏览器  ────────▶│  nginx :80(发布 :8090)                             │
   (lab 局域网 或     │    ├─ /        → React SPA 静态(SPA fallback)       │
    公网经 frp,见§9.5)│    └─ /api/*   → proxy_pass http://web:8090          │
                    └───────────────────────┬──────────────────────────────┘
                                            │ Docker 私网 piks
                    ┌───────────────────────▼──────────────────────────────┐
                    │  piks-web(alpine,纯 Go JSON API,不发布宿主端口)      │
                    │    └─ pgx ──▶ PostgreSQL 16 (:5433 loopback)         │
                    └──────────────────────────────────────────────────────┘
                                            ▲
                    深研触发:web 建 pending 行 + NOTIFY │ worker 认领
                    ┌───────────────────────────────────┴──────────────────┐
                    │  piks-research(python:3.12-slim,常驻队列 worker)     │
                    │    LISTEN piks_research_pending → ClaimPending →      │
                    │    os/exec python3 research/src/cli.py(同容器有解释器)│
                    └──────────────────────────────────────────────────────┘

   管线(cron 每 15min 自判) ──▶ docker compose run --rm tools ./bin/<11 个管线命令>
                               (profile=run,跑一次即退,非常驻)
```

四个镜像各自独立版本、独立升级半径(改前端只重建 gateway;改 Go 只重建 web/tools/research;改 Python 只重建 research)。实测 `docker save` 体积:gateway 25MB / web 8MB / tools 42MB / research 139MB。

| 镜像 | 底座 | 内容 | 职责 |
|---|---|---|---|
| `piks-gateway` | `nginx:alpine` | `nginx.conf` + SPA dist | **唯一对外**入口 :8090;静态 + 反代 `/api/*` |
| `piks-web` | `alpine:3.20` | `bin/web` | 全部 HTTP JSON API;深研只**入队**(写 pending 行 + NOTIFY) |
| `piks-research` | `python:3.12-slim` | `research/` + `bin/research-run` + `bin/research-worker` | Python 运行时 + 深研队列 worker(认领 pending 执行) |
| `piks-tools` | `alpine:3.20` | 11 个管线命令 + `migrations/` + `prompts/` | `profile=run`,跑一次即退 |

> ⚠️ **深研不再在 web 进程内跑**:web 容器已无 python3(拆分后若仍在 web 里 `os/exec python3`
> 就是 2026-09-12 的生产事故复现:`exec: python3: not found`,UI 深研必 failed)。故触发改为
> DB 队列:`migrations/0015` + `cmd/research-worker` + `internal/store/research_queue.go`(LISTEN/NOTIFY)。

三个运行时:

| 运行时 | 位置 | 代码量 | 职责 |
|---|---|---|---|
| **Go** | `cmd/` + `internal/` | 23,891 行(137 个 `.go`:93 生产 + 44 测试) | 采集 / 抽取 / 聚类 / 市场 & 实体 / 对账 / 全部 HTTP API / 深研编排 |
| **Python research** | `research/src/` | 8,353 行(16 个测试文件) | 确定性分析 + 报告装配 + 防幻觉机检(不写库、不调 LLM) |
| **React SPA** | `frontend/src/` | 15,410 行(145 个文件) | 全部 28 条页面路由的呈现层(只读投影 + 交互写) |

> 三者**代码级解耦**:Go 与前端不依赖 research 源码,只经「CLI 参数 + 产物文件契约」交互,
> 由 `scripts/check-research-isolation.sh` 在 CI 校验(见 §5.2);镜像边界由
> `scripts/check-image-topology.sh` 校验(见 §9.1)。
> ⚠️ 拆分未收窄这层解耦:**research 镜像仍由 Go 编译阶段派生**(worker/research-run 是 Go
> 二进制),故改 `internal/research` 会重建 research 镜像 —— 这是 D-11 隔离的一处已知收窄。

### 4.2 零 schema 扩展模式

后期功能**刻意不建表**,复用两种已有结构。这是本项目的稳定习惯,新增能力应优先照此办理。

| 模式 | 载体 | 实例 |
|---|---|---|
| **多态边** | `relationships(from_type, from_id, to_type, to_id, rel_type, properties)` | P6-4 决策记录:`(trade, <trades.id UUID>, research_run\|event\|personal_note, <UUID>, 'based_on')` |
| **JSONB 指标** | `research_runs.metrics` / `entities.detail` | P7 量价逐日序列、P9 章节清单 `metrics.meta.section_manifest`、风险项 `metrics.risk.items` |

> ⚠️ **`to_id` 必须是各表主键 UUID**(研报用 `research_runs.id`,**绝不用** `run_id` TEXT)。
> 无 FK 约束,接错**静默悬空**——这是本项目已踩过的地雷。

### 4.3 图谱隔离(硬约束)

`relationships` 承载业务边与决策边两类。**决策边不得漏进 `/graph`**,否则成为无名节点。

- 过滤点在 `internal/store/relationships.go` 的 `graphRelFilter`:
  `rel_type NOT IN ('decided_by', 'based_on')`
- **仅 `ListAllRelationships` 使用该过滤**;`graph.go` 自己按 rel_type 显式筛选。
- **新增决策边类型必须同步列入 `graphRelFilter`。**

### 5.1 独立性契约(D-11)

| 约束 | 落地 |
|---|---|
| **零共享状态** | `research/` 不 import `internal/` 任何代码 |

### 5.2 CI 守卫

`scripts/check-research-isolation.sh` 校验:
1. Go 侧无 `go:embed.*research`;
2. Go 侧无 `.py"` 引用(白名单 `"cli.py"`);
3. `frontend/src` 无 `research/src` / `research/requirements` / `.venv` 引用;
4. 契约表里写到的产物文件名确实存在于 `research/README.md`;
5. **`exec.Command` 只允许出现在白名单** `internal/research/runner.go`、`cmd/daily-review/main.go`、
   `internal/publish/publish.go`(拆分后 web 容器无 python3,任何**新增**进程执行点都是回退信号)。

`scripts/check-image-topology.sh` 校验镜像边界(见 §9.1):四 target 存在、底座正确、
只有 research 装 Python、tools 逐条 9 命令(拒绝 bulk COPY)、dist 只进 gateway、web 不含 nginx/dist。

`scripts/check-event-type-parity.sh` 校验**事件类型枚举的单一真源**(issue #61):
真源 `model.EventTypes` 自身合法(key 非空唯一、label 非空 —— 漏 label 会让前端静默回落英文);
`extract` 里不得出现任何类型 key 字面量(须经 `model.EventType*` 派生,连兜底桶也不例外);
前端不得再存本地枚举表(按「key 与其事件 label 同行」判定 —— 不能只看 key 字面量,
`industry`/`macro`/`company` 与实体类型、研报 profile 等**正交枚举**撞名,那几处本就该在前端硬编码);
`/api/v1/event-types` 路由在位。前三项均带反向断言(「没漂移」不能是因为压根没接上)。

### 5.3 CLI 契约(三命令,冻结)

```bash
python3 -m src.cli research   <主体码> [--days N] [--profile P] [--out-dir D] [--run-id ID]
python3 -m src.cli synthesize <产物目录> <代码> --synthesis-file <LLM.json> [--prior-metrics <历史metrics.json>]
python3 -m src.cli gate       <产物目录> <代码> [--json]
```

**退出码语义**(非「执行失败」而是「未通过机检」):
`research` 正常出骨架;`synthesize` 在 Number Lint 有 issue 时退 **2**;`gate` 机检未过退 **3**。
两者**都已把结果写进产物文件**,Go 侧据此区分处置(markdown 回落骨架,lint/gate 原样落库)。

**主体码三类**(P9 泛化):公司 `600519` / 行业 `sw801010` / 宏观 `macro:cn_cpi`。
含冒号时 CLI 需加引号;Go 侧走 `exec.Command` **argv 数组**(不经 shell),改 runner 时**不得**改成 `sh -c`。

### 5.7 两层防幻觉

1. **Number Lint**(`number_lint.py`):扫描报告正文,把「不是程序算出来的数字」报为 issue。
   - `(?<!\d)\d{6}(?!\d)(?!\.\d)` 掩码(**6 位股票代码不误判**);
   - `UNIT_SCALES` = 1 / 1e4 / 1e8 单位换算容差;
   - `TEMPLATE_CONSTANTS` 精确匹配;
   - 既往研报数字经 `--prior-metrics` 并入 known 集(让「较上次 +12%」不被误判为编造)。
2. **Quality Gate**(`quality_gate.py`):6 项机检,`gate` 命令输出。
   > 代码实际发 6 项;docstring 曾写 7 项(第 7 项 `no_hallucination` 已由 Number Lint 覆盖)——以**代码为准 = 6 项**。

> **已知技术债**:`_save_artifacts` 从不写 `report_fingerprint`,导致 `run_gate` 的可复现性检查恒短路通过。

**数组字段空态编码为 `[]`,永不 `null`**(issue #59):
Go 的零值 slice 经 `encoding/json` 会序列化成 `null`,而前端 `lib/types.ts` 把
`indices`/`ladder`/`snap_history`/`top_events`/`task_runs`/`facts`/`aliases` 等一律声明为
**非可选数组**并直接 `.map()` —— 契约不一致会在空库时整页白屏(issue #59 即此,
2026-09-20 清库后首页白屏)。故**每个返回数组的 handler 都必须显式初始化空 slice**
(如 `apiDashboard{SnapHistory: []apiSnapRow{}, …}`、`emptyMarketSnapshot()`),
`json.Unmarshal` 结果也要 `if x == nil { x = []T{} }` 兜底。
回归测试:`internal/web/api_dashboard_empty_test.go`(断言**真实 JSON 编码结果**,非 Go 层长度)
+ `api_dashboard_integration_test.go`(临时库跑真实 handler —— 缺陷在「`len(snaps)==0`
这条从未被走到的分支」上,只有真库能到达)。
⚠️ 唯一合法的 `null` 是**语义上真的缺席**的**指针**字段 —— 如 `apiTrades.Account`(无账户快照时 `null`,表示「截图里没这个数」,区别于 `0`),以及 `apiStockHub.Entity`
等;这些在 `types.ts` 里本就是可空类型。

⚠️ **JSONB 数组列同理**(issue #71,不变量 #23):`json.Marshal(nil 切片)` 产出字面量 `null` 且 **`err==nil`**,
守卫若只判 `len(b)==0`(长度 4)会**看不穿并放行** → 落库成 JSON `null` → 消费方
`jsonb_array_elements_text(events.affected)` 遇标量报 **SQLSTATE 22023**,使 `entity-build`
**整条命令崩掉**(不是跳过坏行;实测当日 18/18 全失败)。修法三层:
写入侧 `extract.mustJSONArray` + `store.emptyToArrayIfScalar`(按**语义值**判定 nil/空/标量 → `[]`)、
消费侧 `ListAffectedTermEvents` 加 `jsonb_typeof(affected)='array'`(纵深防御)、
历史脏行由 `scripts/fix-events-affected-null.sql`(幂等)清理。

### 6.5 🔴 热榜独立链路(issue #68 D 层)

热榜与事件链路**在结构上隔离**,不是纪律约束而是**类型约束**:

| 维度 | 事件链路(快讯/公告) | 热榜 |
|---|---|---|
| 接口 | `Driver` / `RawNews` | **另立** `HotTopicSource` / `HotTopicItem` |
| 落库 | `raw_documents` → `events` | **独立表** `hot_topic_items`(迁移 `0018`) |
| 进程 | `collector`(compose 服务) | **独立** `hot-topic` 服务(同 `piks-tools` 镜像) |
| 聚类 | ✅ 参与 | ❌ 不参与 |
| 消费方 | `worker` → LLM → events | `GET /api/v1/hot-topics` → 独立页 |

**为什么必须隔离**:热度**可被商业力量操纵** —— 若混入事件链路,就等于把「多少人关注」
混进「几家机构证实」(印证度 `source_count`/`cluster_sources`)。二者**正交**。
故 `hottopic.go` **刻意不复用** `Driver` 接口,热榜数据在**类型上就无法**流入事件链路;
`ListAllRelationships` 的图谱过滤同理(新增边类型须列入)。

**两源不合并**:同花顺话题榜(题材/事件)与财联社热文(文章/复盘)**粒度不同**,
实测 615 对标题**同题对 = 0**(J≥0.5 仍 0),热度量纲也不同(且各源自身尺度也差)
→ **各出各的、不合并、不加权、不排名**,接口**按源分列下发**(结构上杜绝混排)。

红线细则见 `docs/phase11/design/hot-topic.md` §3(含「名次是事实,不得重排」
—— 实测财联社数组顺序 ≠ `readNum` 降序,`rank` 取数组下标 + 1)。

**公告(issue #50)**:`collector -driver cninfo-announce` 跑巨潮全市场个股公告(~1200 条/日),
落 `source_type='announcement'` / **`status='collected'`** —— **不进 LLM 抽取**
(worker 只取 `status='raw'`),也不报对账异常(`processed_no_event` 只看 `status='processed'`)。
前端在消息页「公告」tab 呈现(`GET /api/v1/announcements`);快讯投影已显式排除 announcement。
**只存标题 + 原文 PDF 外链,不存正文**(正文抓取实测被上游 IP 级限流,见
`docs/phase11/design/announcement-source.md` §3)。

**公告分级(issue #68 S1)**:采集时按**标题关键词规则**给 `raw_documents.grade` 打分
(`internal/announce`,纯函数),前端公告 tab **默认只显必读+重要**、其余一键展开,
解决 ~1200 条/日「全平铺看不过来」。⚠️ **只落标签,`status='collected'` 不变** ——
公告仍不进 LLM(分级**不产生成本收益**,价值纯在展示层);`grade=NULL`(非公告源/历史行)
按「常规」显示,**只折叠、不隐藏**。设计 `docs/phase11/design/announcement-grading.md`。

**采集入库失败语义(issue #64)**:`cmd/collector` 的单源 `runOne` 按**结局**记 `task_runs` ——
fetch 到但**一条都没落库** ⇒ `status='failed'` + 返回 error ⇒ **退出码非零** ⇒ `pipeline.sh`
记 FAIL 且**不写** `.done` 戳(当日可重试);**部分**落库失败 ⇒ `status='partial'`(不是 `success`),
单条坏数据不拖垮整源(免费源无 SLA 是 #43 既有纪律);`dup` 不计失败。
旧实现无论 `failCount` 多少都记 `success` + 返回 `nil`,`meta.failed` 又**无读取方** ⇒
「采到 0 条而全链报绿」(迁移 0016 事故形态:123/123 全失败仍 exit 0)。
前端 `toTaskRun` 补 `partial` 分支 + `failed` 字段,`Pipeline.tsx` 在 `failed>0` 时显示「N 条未入库」。
⚠️ `toTaskRun` 的 `switch` **未匹配状态一律落 `running`** —— 新增状态必须同步改它(见 §9 不变量)。

**聚类候选池(issue #53)**:`cmd/cluster` 的 `-limit` 默认 **0 = 不限**(取全部未聚类事件)。
此前默认 `-limit 100` + `ORDER BY created_at ASC` 只取最旧 100 条,超出部分**静默丢弃**
(`task_runs` 仍记成功)→ 积压时新事件永远轮不到,并被 `source_count` 语义误标成「单一来源」。
显式传 `-limit>0` 时用 `store.UnclusteredEventsTruncated` 探测并把 `limit`/`truncated`
记进 `task_runs.meta` + 打 WARN。

**聚类候选池收敛(issue #75)**:`-limit 0` 只解决「不截断」,**不解决「池永不排空」** ——
`BuildComponents` 只保留 `len(m)>=2` 的分量,从未匹配上对端的事件永远拿不到 `cluster_id`,
故每轮被重新 O(pool²) 配对 + 送 LLM(生产 `unclustered = 1915/4083`,实测单日 ≈ 2350 万 token)。
修法 = **扫描水位** `events.cluster_scanned_at`(迁移 `0019`):本轮进池、比对过、最终不属于任何分量
的事件盖戳,`ListUnclusteredEvents` 加谓词 `cluster_scanned_at IS NULL` ⇒ 下轮只扫**新入库**;
`-limit>0` 截断时**整体跳过**盖戳(没比对过就判「无对端」= 永久漏召回)。
⚠️ **戳不是「建单例簇」的等价物** —— 盖戳事件 `cluster_id` 仍为 NULL、**不是活跃簇代表**,
若不处理会**从正常 pass 与重审视两处同时消失** ⇒ 重审视池必须**显式并入窗口内已盖戳事件**
(`ScannedEventsSince`),这是召回等价的唯一保证。选盖戳而非单例簇的实测理由:单例簇会让
`GET /api/v1/events`(`handleAPIEvents` 的 `clusterIDs`)从「多源簇数」涨到**每个可见事件**,
每次都要把全部事件的 `facts` JSONB 读一遍(无 LIMIT,全站最热接口)。
**重审视时间窗** `-window-days`(默认 7):池按**簇内成员 `MAX(created_at)`** 收窗
(⚠️ 不能用代表/最早成员的 `created_at` —— 会把「刚并入新成员的老簇」整个排除,而那最该进池;
`event_clusters.updated_at` 亦不可用,多处并入路径不 bump);召回边界如实登记:
相隔超过窗口才到达的重复事件不会被配对(实测全部 746 个多源簇成员跨度**均 ≤ 1 天**,7 天有 7 倍余量)。
另有 `-dry-run`(只生成候选、不调 LLM、不写库)。

**预算 = 0 的语义(issue #75)**:`ai_daily_token_budget=0` 意为**护栏关闭**(不是「不限预算」)——
`cmd/cluster`/`cmd/worker` 为 0 时打 WARN 并在 `task_runs.meta` 记 `guard_disabled=true`,
预算耗尽记 `budget_exhausted=true`;须经 `/settings` 设为非 0(建议 `1000000`)。
日界口径统一为**北京午夜**(`config.BeijingMidnight`),替换原先按 **UTC** 对齐的 `Truncate(24h)`
(后者 = 北京 08:00,与「日预算」直觉不符)。

**事件类多源(issue #43 T1)**:`collector -driver all` 依次跑 6 个**独立机构**源
(东方财富 / 金十数据 / 财联社 / 新浪财经 / 同花顺 / 富途资讯),每源落各自 `sources` 行
(name = **机构名**);单源失败**不阻断**其余源(免费源无 SLA)。各源上游原始字段
(`reading_num` / `important` / `data.source` / `like_nums` …)原样落 `raw_documents.extra`。
⚠️ 同机构不同端点不算独立源 —— Go 东财与 akshare `stock_info_global_em` 同为东财,只能算一个。

**跨源同事件判定(issue #43 T2 / #48)**:cluster 跑在 **`events`(抽取后)** 上,不是
`raw_documents` 上 —— 多源先在抽取层各自成 event,再由 cluster 合并。跨源标题写法分两类
(东财/新浪 = `【标题】`+公告正文;财联社/金十/同花顺/富途 = 裸标题),原句全文比对会把
**同一事件**的相似度稀释到阈值下(实测东财 vs 财联社同一天山生物减持 = 0.165)。
故 `NormalizeTitle` 前置 `stripBracketWrap` **抽取 `【】` 内嵌标题前缀**(≥6 字才当标题,
否则视为栏目标签)→ 相似度还原,**阈值 0.7 不动**(红线「扩候选池不降门槛」;实测降门槛
不增加专属召回)。簇内来源经 `store.ListClusterSources` 读回(**含 `merged` 成员**),
`/api/v1/events` **仅跨源簇(≥2 机构)** 下发 `cluster_sources`(机构名 + 原文链接 +
上游一级源 `extra->>'source'`),前端事件详情/表格展示「N 家印证」。**零 schema**。
详见 `docs/phase11/design/event-cross-source.md`。

**漏报 / 冲突检测(issue #43 T3 / #49)**:同一读路径再补两件事 ——

- **单源可见**:新增 `source_count`(**机构级**去重计数,未聚类 = 1)。⚠️ `cluster_sources` 是
  `omitempty`,**单源与未聚类都不下发**,光看它分不清「就 1 家」和「还没聚类」,故必须用显式计数。
  `=1` 前端标「**单一来源**」(中性措辞,**不说可疑** —— 独家报道很常见;绝不丢弃任何事件)。
- **冲突可见**:`internal/cluster/conflicts.go` 纯规则数值比对 —— 单位白名单锚定数字,
  骨架 Jaccard(只删数字**不删汉字**,否则「回购 vs 增持」误报)≥ **0.6** 才配同一句,
  两侧各恰好 1 个不同值才报。**留双方原文**(`sentence_a`/`sentence_b`),前端两条都渲染,
  **禁止静默择一**(Fact ≠ Inference)。门控按生产 1410 条真实事实句标定(随机句对误报 **0.0750%**,
  同标题重复组 **0 差异**,对抗集 **0/4**);远改写召回的已知边界如实登记,**留给 #45**。
  **零 schema**(读路径派生,与 `cluster_sources` 同范式)。

**转载不计入独立来源(issue #83 P-1)**:`source_count` 是**机构数**,但 `raw_documents` 去重键含
`source_id`,**同一篇通稿被两家近逐字转载会落两行** → 机构数被刷高 → 印证度三级全废。
同一读路径再加 `independent_count`(**独立来源数**):`internal/cluster/reprint.go` 纯函数对簇内
各机构**代表正文**(`ListClusterSources` 增读 `rd.content`)跑字符二元组 Jaccard,**≥ 0.85 视为同一篇稿**、
并查集合并为一源;独立来源数 = 组数,逐来源下发 `reprint` 布尔供前端标「(转载)」。
🔴 **两条实测反例定死实现形态**:① **不得用标题指纹**(同事件标题天然收敛,会把独立报道误判成转载,
方向与目标相反);② **不得复用 `NormalizeTitle`**(内含 `stripBracketWrap` 抽【】内正文 → 裸标题与
「【同标题】+正文」J=1.000,实测 **156 对**误判)→ 指纹取 **content 原文**(`NormalizeReprintContent`
只去电头/HTML 标签)。校准(lab 库 398 多机构簇 / 2735 跨机构对):强双峰,门控 **0.85**
(0.80 下沿全真转载,0.75~0.80 全改写);@0.85 **50.0%** 簇独立来源 < 机构数、**39.9%** 由「≥2 家」
跌到「恰好 1 个独立来源」。⚠️ `SourceCount`(**机构数**)语义不变,印证度三级改看 `IndependentCount`;
改写型转载漏判的残余上限如实登记。**零 schema**(读路径派生)。
详见 `docs/phase11/design/reprint-stripping.md`。

`scripts/pipeline.sh` 的**闸门与护栏**(issue #76 起):
- **单实例锁 `flock -n`**(锁文件 `logs/pipeline.lock`):上一轮未结束时下一 tick 直接退出并
  在 `cron.log` 记一行「另一管线实例仍在运行」⇒ 消灭并发管线(锁随进程退出自动释放);
- **日期锚点取 GitHub `Date` 响应的 `Date` 头**(免疫宿主机时钟漂移),取不到才回退系统时钟并打显式 WARN;
- 周末跳过;早于 16:10(北京时间)跳过;当日 `pipeline-$TODAY.done` 已存在则跳过(快速路径);
- **步骤台账 `pipeline-$TODAY.done.d/<step>.done`**:每完成一步 touch 一个文件,**下一 tick 只跑未完成的步骤**
  (不再「任一失败 → 全部重跑」);`pipeline-$TODAY.fail.<step>` 记当日失败次数;
- **单步超时** `timeout --signal=TERM --kill-after=30s ${PIKS_STEP_TIMEOUT:-1800}s`:单步挂起不再堵死整条链
  (实测曾堵 2h25m)。⚠️ 边界:`timeout` 杀的是 `docker compose run` 客户端,容器本身可能不被回收;
- **失败分型 + 退避**:`deterministic`(SQLSTATE/constraint/does not exist)与 `quota`(429/rate limit/
  insufficient balance)⇒ **立即放弃**、当日不再重试并记 `== ABANDON`;`transient`(瞬断)与 `timeout` ⇒
  计次重试,达 `PIKS_MAX_RETRY`(默认 5)后当日放弃。放弃是**需人工介入**的终态,不静默。
- 全链全部完成才落 `.done`;任一步失败/放弃则不落(但**已完成的步骤不再重跑**)。
- ⚠️ `.done` 的存在 = 「今日全链已跑完」凭证,与旧语义一致;「未完成」的判定须看**台账**
  (`scripts/health.sh` 已同步,含升级过渡日「旧格式 stamp 无台账目录」的兼容)。

### 8.2 深研 run 状态机(2026-09-20 起为 DB 队列驱动)

```
pending → gathering → synthesizing → verifying → done | failed
```

- Go `internal/research/runner.go` 用 `os/exec python3` 调 CLI 三命令,**argv 数组不经 shell**;
- **触发入口两种**(UI 与 CLI):
  - **UI 按钮**(`POST /api/v1/research-runs`):web 只做三件事 —— 建 `pending` 行
    (`CreateResearchRun`)、`NOTIFY piks_research_pending`、返回 `{run_id,status}`
    (响应形状与拆分前逐字不变)。**执行在 research 容器的常驻 worker**,不在 web 进程内。
  - **CLI 旁路**(`docker compose exec research ./bin/research-run 000560`):绕过队列直接跑,
    供排障/回填。
- **队列实现**(issue #47 拆分引入,零 schema 变更语义 + 迁移 0015 两列):
  - `internal/store/research_runs.go` `ClaimPendingResearchRun`:`UPDATE … WHERE run_id =
    (SELECT … WHERE status='pending' ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED)`
    —— 单条语句原子领取,`SKIP LOCKED` 天然支持多副本;**并发安全**。
  - `cmd/research-worker`:`LISTEN/NOTIFY` 加速(实测 `-poll 60s` 下通知同秒唤醒)+
    轮询兜底(通知丢失不影响正确性)。`SIGTERM` 只停**认领**,在跑的 run 用
    `context.Background()+TimeoutTotal` 跑完(compose `stop_grace_period 7m`)。
  - **孤儿回收**:`ReapStuckResearchRuns(grace)` 回收 `updated_at` 超期(grace =
    `TimeoutTotal + 2min` = 8min)的进行中 run → `failed`,诚实地登记中断而非永久卡住。
  - ⚠️ 旧 `researchRunStale` 启发式已删 —— web 不再判断谁在跑(它无从知道),收口归 worker 的 reaper。
- **运行参数随行落库**(迁移 0015 的 `quick`/`days` 两列):worker 只拿得到 `research_runs`
  这一行,不落库则认领后无从还原 `RequireSynthesis`(quick)与回溯天数。
- **危险点**:`runner.go` 的 argv 传参不得改成 `sh -c`,否则 `macro:cn_cpi` 的冒号有注入面。

## 9. 部署拓扑

### 9.1 四镜像(2026-09-20 定,取代 2026-09-12 单镜像 D-2)

单 `Dockerfile`(多 target,而非四个文件 —— Go 与前端构建阶段在四镜像间完全共享):

| 阶段 | 底座 | 内容 |
|---|---|---|
| `build` | `golang:1.26-alpine` | `go build ./cmd/...` → `/out/bin/`(`-s -w` 去符号表,-trimpath) |
| `frontend` | `node:20-alpine` | `npm run build` → `dist/` |
| `gateway` | `nginx:alpine` | `nginx.conf` + `--from=frontend dist` |
| `web` | `alpine:3.20` | `--from=build bin/web` |
| `tools` | `alpine:3.20` | 11 个管线命令(逐条 COPY)+ `migrations/` + `prompts/` |
| `research` | `python:3.12-slim` | pip 装 `research/requirements.txt` + `research/` + `research-run` + `research-worker` |

```bash
docker build --target gateway  -t piks-gateway:latest  .
docker build --target web      -t piks-web:latest      .
docker build --target tools    -t piks-tools:latest    .
docker build --target research -t piks-research:latest .
```

- **cache 击穿已修**:`build` 阶段只 `COPY cmd/ internal/ go.mod go.sum`(**不含 `frontend/`**)。
  原先 `COPY . .` 让改一行 `frontend/src/main.tsx` 就击穿 Go 层、全部二进制重编(实测 27s)。
- **research 必须留 debian slim**:akshare/pandas 无法在 musl 上构建,反向「nginx:alpine 上
  apk add python3」不可行。
- **tools 逐条 COPY 11 个命令**,不用 `COPY --from=build /out/bin/ /app/bin/`:后者会把
  `web`/`research-run`/`research-worker`/`probe` 也塞进 tools,既白占体积又让误用成为可能。
- 构建参数:`GOPROXY` · `APK_MIRROR` · `APT_MIRROR` · `PYPI_INDEX`(deploy.sh 默认 USTC 源,见下)·
  `GIT_SHORT` · `PIKS_VERSION`(默认 `v0.0.0`)。各镜像烘焙 `PIKS_GIT_SHORT` + `PIKS_VERSION` +
  **`PIKS_IMAGE_ROLE`**(`gateway`/`web`/`tools`/`research`,供自证是哪个镜像)。
  ⚠️ `ARG GIT_SHORT`/`ARG PIKS_VERSION` 必须声明在**首个 FROM 之前**(全局作用域)——
  在阶段内声明的 ARG 只对该阶段可见,后续阶段取不到它的默认值。
- ⚠️ **PyPI 源默认 USTC,不用 aliyun/清华**(issue #57 首修,2026-09-22 复测再优化):
  `deploy.sh` 的 `PYPI_INDEX` 默认 `https://mirrors.ustc.edu.cn/pypi/simple`。
  **完整装 `requirements.txt` 逐源实测**(非单包):aliyun **202.7s** / 清华 18.2s /
  pypi.org 9.8s / **USTC 8.8s** —— 即 ① aliyun 仍最慢(慢 23 倍,#57 时代结论仍成立);
  ② **清华也不是最优,USTC 再快约 2 倍**。单包下载复现同序(aliyun 32.8s vs USTC 1.8s)。
  **这是取数链路的环境事实,非永久结论** —— 换线路/换构建机后应重测。
- ⚠️ **apt 源默认 USTC(research 阶段,2026-09-22)**:`Dockerfile` 的 `APT_MIRROR` 默认
  `mirrors.ustc.edu.cn`(此前为 aliyun)。容器内 `apt-get update` 三轮实测:
  aliyun **~18.6s** / 清华 ~6.6s / deb.debian.org 2.2s / **USTC ~1.8s** —— **aliyun 慢 10 倍**。
  USTC 的 `debian-security` 路径与 deb.debian.org 一致(`/debian-security`),`sed` 替换无需额外处理。
  两源(apt + pip)都换 USTC 后,**research 冷构建实测 157.9s → 37.7s**(快 4.2 倍)。
  ⚠️ 同属环境事实,换构建机需重测。
- ⚠️ **`ARG GIT_SHORT`/`ENV PIKS_GIT_SHORT` 必须排在 `pip install` 之后**(research 阶段):
  它是**每次提交都变**的元数据,若排在依赖安装之前,则每次部署都让 pip 层缓存失效、重下
  全部依赖(实测把构建拖到数十分钟)。移到之后 → 只要 `requirements.txt` 不变,pip 层永久
  命中缓存(实测 `GIT_SHORT` 由 `test` 改 `zzz9` 重建,pip 层 `Using cache`、层 ID 不变)。
  其余三 stage 的 `ENV` 之后只有 `COPY`(无网络操作),故无此问题。
- ⚠️ legacy builder(本机 Docker 29,无 buildx)支持 `--target`,但**无 `--mount=type=cache`**:
  Go 阶段源码变动时仍会重编,本期只消除「前端改动击穿 Go 层」。**禁写 `# syntax=` 指令**
  (需 BuildKit,会硬失败)。

**`scripts/check-image-topology.sh`** 在 CI 断言这张表:四 target 存在、底座正确、只有
research 装 Python、tools 逐条 11 命令(拒绝 bulk COPY)、dist 只进 gateway、web 不含 nginx/dist。

### 9.3 nginx(`configs/nginx.conf`)

单 server :80;`client_max_body_size 10m`;gzip;`/` → `try_files … /index.html`(SPA fallback);
`/api/` → 反代 **`http://web:8090`**。

> ⚠️ **`resolver` + 变量式 `proxy_pass` 是必须的,不是优化**:nginx 对 `proxy_pass` 里的字面
> 主机名只在 worker 启动时解析一次并缓存到进程结束;web 每次重建都换 IP,于是 `deploy.sh`
> 每跑一次 `up -d web`,gateway 就会 502 到自己被重启。改用 Docker 内嵌 DNS(`127.0.0.11`)
> + `set $piks_web "http://web:8090"; proxy_pass $piks_web$request_uri;` 才会按 `valid=` 重解析。
> ⚠️ 变量式 `proxy_pass` **不会自动带原 URI**,必须显式拼 `$request_uri`,否则 `/api/v1/x` 会请求成 `/`。

### 9.4 部署流程(`scripts/deploy.sh`)

```
每镜像 VER 全局唯一(git describe --tags --exact-match || v0.0.0)
     版本 hash 由该镜像**自己的输入集**派生:
       前端 = 整个 frontend/ 的 tree;Go = `go list -deps` 的真实依赖闭包;
       四处均含整文件 `Dockerfile`(**tools 的 Go 闭包取 10 个命令的并集**,见下)
build --target <role>(tag 已存在则跳过)→ save|load(仅传 lab 上缺的 tag)
     → scp compose + scp lab 侧 scripts/ → up -d postgres → run --rm tools ./bin/migrate
     → up -d web research collector hot-topic watch-sync → up -d gateway → 落 stack 清单
```

- **按镜像判定重建/传输**:改前端只改 gateway 的版本 hash,web/tools/research 的 tag 不变
  → 既不重建也不传输。这正是拆分要换来的东西(代价见下)。
- ⚠️ **输入集必须覆盖该镜像构建真正读的每个文件**:少算 = 「改了文件、tag 不动、不重建不传输,
  生产跑旧像」的**静默错误**(比多算严重)。故 Go 用 `go list -deps` 取真实闭包而非手列目录
  (实施中实测漏过 `internal/model`);前端整树覆盖。
  ⚠️ **四处输入集都含 `Dockerfile` 整文件**(issue #55 补):此前 Dockerfile **不在任何输入集里** ——
  改了 Dockerfile 也不改 tag → `build_image` 判定「已存在、跳过构建」→ 修好的镜像既不重建也不传输,
  生产静默跑旧像,**修复本身失效**。取整文件 hash(改注释也触发重建)是**故意的**:方向安全
  (宁可多重建,不可漏),且 Dockerfile 极少改动。
  ⚠️ **`tools` 的 Go 闭包必须取全部 11 个管线命令的并集**(`go_deps_hash_all`):tools 镜像虽以
  `migrate` 触发构建,却**打包全部 11 个命令** —— 若只 hash `migrate` 的闭包(仅
  `config`/`model`/`store`),则改 `internal/collector/` 而 `TAG_TOOLS` 不动 → 同样「生产跑旧像」。
  实测(issue #68 C 层)新增常驻 `collector` 服务曾以**旧 tools 镜像**启动、新代码根本没上。
  新增管线命令时**必须同步**此处(build 与 `TAG_TOOLS` 两处)与 `check-image-topology.sh`
  (D 层加 `hot-topic`、#87 加 `watch-sync` 时三者均一并改)。
- **干净树门控**:镜像从**工作树**构建却以**版本 tag** 命名,工作树脏时 tag 与内容不符。
  默认拒绝;确需调试用 `PIKS_ALLOW_DIRTY=1`(tag 附 `-dirty`)。
- **顺序是硬约束**:
  1. migrate **必须先于 web** —— `cmd/web/main.go` 启动即读 `app_config`,缺表会 fatal 崩溃循环;
  2. gateway **必须最后** —— 否则 nginx 会短暂反代半启动的 web(compose 的
     `depends_on: web(service_healthy)` 是第二道保险)。
- **未发版恒 `v0.0.0`**;正式发版才在 master 打语义 tag。每次部署**保留回滚镜像**
  `<name>:rollback-pre-<阶段>`(拆分前单镜像另存 `<name>:rollback-pre-<阶段>-single`)。
  ⚠️ **快照只打一次、存在即跳过**:回滚点是一次性的,无脑 `docker tag latest rollback-pre-X`
  会在第二次部署时把它静默改写成新镜像(标签与内容不符);`-single` 从已知拆分前 tag
  (`PIKS_PRE_SPLIT_REF`,默认 `piks-tools:v0.0.0-b996864`)取而非 `latest`。
- lab(192.168.0.202)**不保留代码仓库,镜像 = 唯一交付物**,编排全在 dev 侧。
- ⚠️ **`scripts/` 随部署同步**(issue #49 补):此前只 `scp` compose,lab 侧 `scripts/` **从不同步** ——
  实测 lab 的 `pipeline.sh` 长期停在 `-driver dongcai`(仓库早已 `-driver all` 六机构源),
  **编排与代码版本脱钩,6 源一条没采**。现 deploy.sh 一并 `scp` lab 上运行的脚本
  (`pipeline.sh`/`backup.sh`/`health.sh`/`setup.sh`,dev 侧 `check-*`/`fix-*` 不上 lab)并 `chmod +x`。
- **stack 清单**(`/home/rguo/piks/stack-manifest.json`):记录本次上线的四镜像 tag + commit,
  是「生产在跑什么」的单一答案。
- ⚠️ **拆分不减总量**:四镜像合计 `docker save` ~214MB(gateway 25 / web 8 / tools 42 /
  research 139),与旧单镜像 ~216MB 基本持平。**收益是升级半径,不是流量** —— 但按镜像传输后,
  改前端只传 **25MB**(gateway)而非整镜像 216MB;改 Go 只传 50MB(web+tools);改 Python 只传 139MB。
  如实如此,不夸大为「省流量」。

### 9.5 公网暴露(`piks.5home.online`,2026-09-22,issue #78)

生产全栈**仍跑在 lab**(`192.168.0.202`);公网入口是**阿里云宿主机上的边缘 Nginx**,经
**frp 隧道**回源到 lab —— 阿里云不跑任何 PIKS 业务进程,只做入站。

```
公网 ──▶ 阿里云宿主 Nginx(443, SNI 分流 piks.5home.online)
        └─ proxy_pass http://127.0.0.1:17010
             │  (frp **stcp visitor**,只绑 127.0.0.1,secretKey 鉴权)
             ▼
        frps:17000(阿里云,host 网络)
             │
             ▼
        lab 的 frpc(stcp client,~0600 配置)
             └─ ▼ 127.0.0.1:8090(lab 上 piks-gateway —— **不变**,与局域网访问同一入口)
```

- **回源口 `17010` 只绑宿主机 `127.0.0.1`**(stcp visitor 的 `bindAddr`),公网不可达

- **边缘配置在 `/root/host-infra`(阿里云宿主机,非本仓库,不入 git)**:vhost 模板
  `nginx/conf.d/piks.conf.tmpl`(占位符 `__PIKS_DOMAIN__`)、域名键 `PIKS_DOMAIN=piks.5home.online`
  (`/etc/host-infra/edge.env`)、`scripts/deploy.sh` 渲染后落 `/etc/nginx/conf.d/99-vhosts.conf` 并 reload。
  证书复用通配符 `*.5home.online`,不单独签。
- ⚠️ **模板不得声明 `default_server`**:443 的 `default_server` 归 `ai-gateway.conf.tmpl`(未知主机名
  一律 `444` 断开);piks vhost 再加会 `nginx -t` 报 duplicate default server。
- ⚠️ **`client_max_body_size 32m` 是本 vhost 显式所加**:公共 snippet `proxy-common.conf` 不设,
  继承 Nginx 默认 1m,而 PIKS 有截图导入(交易/持仓/自选)上传,不放大则大图 413。
- ⚠️ **明文 http 回源**:PIKS gateway 自身只做 SPA 静态 + `/api/*` 反代,无 http→https 跳转;
  边缘也不为 80 建站(与本仓库「只用 443」一致),故只从 https 访问。
- ⚠️ **裸奔(无鉴权)**:`internal/web/server.go` 全部路由无 auth,公网可读写全部业务数据 +
  触发 LLM(真实计费)。**已知缺口,跟踪 issue #78**,待补鉴权(边缘 Basic Auth / mTLS / 应用层登录)。
  在补齐前,务必确认 `ai_daily_token_budget` 预算闸已生效(依赖 #75),否则公开接口可被刷 token。
- ⚠️ **唯一为 #78 单独加的写入闸 = 同花顺凭据**(issue #87):`POST /settings` 的 `ths_*` 三键
  **默认拒写**(需 `PIKS_ALLOW_THS_CRED_UI=1`),否则攻击者可覆盖凭据把你锁在门外;
  `/settings/form` 只回掩码。**其余写入面仍是裸的** —— 这是止血,不是修 #78。

## 12. 边界(明确不做)

- **不自动交易 / 不荐股 / 不发买卖信号 / 不接资金 / 不做高频行情**。
  交易功能只做「记录 + 解读 + 诊断」——不连券商、不下单、不做信号。
- 与 steady **领域耦合**:不共享表、不互相调用,DB 级完全隔离(独立 Postgres 实例)。
- 不上:队列框架 / Elasticsearch / Neo4j / Kubernetes / 微服务 / 多 AI Agent / 十几个数据源。
  任务调度 = cron + PG 任务表。
