## 0. 一句话定位

PIKS 是 **Knowledge System,不是 Trading System**。

核心价值 = 「**我终于能解释为什么市场发生了这件事**」,而不是「明天买什么」。

形态:A 股个人投研平台。把公开市场信息(快讯、涨停池、行情、龙虎榜、财务、行业指数、宏观指标)
自动加工为**结构化事件与实体**,沉淀进 PostgreSQL;再经 React 界面完成
**研究 → 决策 → 持仓 → 复盘**的个人闭环。

## 1. 三条冻结骨架(不可违背)

贯穿全部代码的三条硬约束。任何新功能都不得绕过。

| # | 骨架 | 在代码中的落点 |
|---|---|---|
| 1 | **PostgreSQL = Source of Truth** | 13 个前向迁移(0001~0013)建 21 张表 + 运行时 `schema_migrations` 记账表;Markdown/Obsidian 投影层已于迭代 5-2 下线,`PIKS-Vault/` 仅存档 |
| 2 | **Fact ≠ Inference ≠ Belief** | 研报三域标记 `fact 数据 / calc 计算 / opinion 研判`(`lib/constants.ts` `DOMAIN_LABEL`);`metrics` 是**数字唯一源(Fact)**,LLM 只写 `opinion` |
| 3 | **AI 不直接写库** | `AI → Structured Output → Schema Validation → Business Validation → Knowledge Core`。AI 输出先落 `raw_documents`/task 中间态,经校验才进知识核心;research 侧另有 Number Lint + Quality Gate 两道机检 |

> 骨架 3 的具体体现:深研 LLM **从不触碰数值**——所有数字由 Python 确定性计算出,LLM 只写三段定性叙述,
> 写完后由 Number Lint 反向扫描报告正文,把「不是程序算出来的数字」全部报为 issue。

## 2. 系统全景

PIKS 是**同仓三运行时、单镜像交付**的个人系统。

```
                    ┌──────────────────────── 单镜像 piks-tools ────────────────────────┐
                    │  (底座 python:3.12-slim)                                          │
   浏览器  ────────▶│  nginx :80 ──┬─ /            → React SPA 静态(SPA fallback)      │
   (lab 局域网)     │   (发布:8090) │                                                     │
                    │              └─ /api/*       → Go web 127.0.0.1:8090              │
                    │                                                                    │
                    │  Go web ──── pgx ──▶ PostgreSQL 16 (:5433 loopback)                │
                    │     │                                                              │
                    │     └─ os/exec python3 ──▶ research(Python 深研运行时,同容器)      │
                    └────────────────────────────────────────────────────────────────────┘

   管线(cron 每 15min 自判) ──▶ docker compose run --rm tools ./bin/<9 个管线命令>
```

三个运行时:

| 运行时 | 位置 | 代码量 | 职责 |
|---|---|---|---|
| **Go** | `cmd/` + `internal/` | 17,876 行(82 个 `.go`:58 生产 + 24 测试) | 采集 / 抽取 / 聚类 / 市场 & 实体 / 对账 / 全部 HTTP API / 深研编排 |
| **Python research** | `research/src/` | 8,353 行(16 个测试文件) | 确定性分析 + 报告装配 + 防幻觉机检(不写库、不调 LLM) |
| **React SPA** | `frontend/src/` | 12,438 行(135 个文件) | 全部 27 条页面路由的呈现层(只读投影 + 交互写) |

> 三者**代码级解耦**:Go 与前端不依赖 research 源码,只经「CLI 参数 + 产物文件契约」交互,
> 由 `scripts/check-research-isolation.sh` 在 CI 校验(见 §5.2)。

### 4.2 零 schema 扩展模式

后期功能**刻意不建表**,复用两种已有结构。这是本项目的稳定习惯,新增能力应优先照此办理。

| 模式 | 载体 | 实例 |
|---|---|---|
| **多态边** | `relationships(from_type, from_id, to_type, to_id, rel_type, properties)` | P6-4 决策记录:`(trade, <trades.id UUID>, research_run\|event\|personal_note, <UUID>, 'based_on')` |
| **JSONB 指标** | `research_runs.metrics` / `entities.detail` | P7 量价逐日序列、P9 章节清单 `metrics.meta.section_manifest`、风险项 `metrics.risk.items` |

> ⚠️ **`to_id` 必须是各表主键 UUID**(研报用 `research_runs.id`,**绝不用** `run_id` TEXT)。
> 无 FK 约束,接错**静默悬空**——这是本项目已踩过的地雷。

### 4.3 图谱隔离(硬约束)

`relationships` 承载业务边与决策边两类。**决策边不得漏进 `/graph`**,否则成为无名节点。

- 过滤点在 `internal/store/relationships.go` 的 `graphRelFilter`:
  `rel_type NOT IN ('decided_by', 'based_on')`
- **仅 `ListAllRelationships` 使用该过滤**;`graph.go` 自己按 rel_type 显式筛选。
- **新增决策边类型必须同步列入 `graphRelFilter`。**

## 5. Python research 子系统

### 5.1 独立性契约(D-11)

| 约束 | 落地 |
|---|---|
| **零共享状态** | `research/` 不 import `internal/` 任何代码 |
| **产物契约版本化** | `run_meta.json` 的 `contract` 字段(当前 `1`);Go 侧遇不支持的高版本**如实失败** |
| **依赖独立** | `requirements.txt` 不进 Go/前端依赖链 |
| **接口冻结** | CLI 三命令 + 产物文件名冻结;加能力可加命令,**不改既有语义** |
| **独立测试** | `pytest tests/`,纯 Python + provider mock,不依赖 PIKS 与数据库 |

### 5.2 CI 守卫

`scripts/check-research-isolation.sh` 校验:
1. Go 侧无 `go:embed.*research`;
2. Go 侧无 `.py"` 引用(白名单 `"cli.py"`);
3. `frontend/src` 无 `research/src` / `research/requirements` / `.venv` 引用;
4. 契约表里写到的产物文件名确实存在于 `research/README.md`。

### 5.3 CLI 契约(三命令,冻结)

```bash
python3 -m src.cli research   <主体码> [--days N] [--profile P] [--out-dir D] [--run-id ID]
python3 -m src.cli synthesize <产物目录> <代码> --synthesis-file <LLM.json> [--prior-metrics <历史metrics.json>]
python3 -m src.cli gate       <产物目录> <代码> [--json]
```

**退出码语义**(非「执行失败」而是「未通过机检」):
`research` 正常出骨架;`synthesize` 在 Number Lint 有 issue 时退 **2**;`gate` 机检未过退 **3**。
两者**都已把结果写进产物文件**,Go 侧据此区分处置(markdown 回落骨架,lint/gate 原样落库)。

**主体码三类**(P9 泛化):公司 `600519` / 行业 `sw801010` / 宏观 `macro:cn_cpi`。
含冒号时 CLI 需加引号;Go 侧走 `exec.Command` **argv 数组**(不经 shell),改 runner 时**不得**改成 `sh -c`。

| 文件 | 产出者 | 内容 |
|---|---|---|
| `run_meta.json` | research | `run_id`/`symbol`/`profile`/`mode`/`as_of`/`sections`/`provider_calls`/**`contract`** |
| `{code}_metrics.json` | research | 指标卡(**数字唯一源**)+ Evidence 链;`meta.section_manifest` = 章节清单 |
| `{code}_skeleton.md` | research | 骨架报告(模板槽位,数字已渲染) |
| `{code}_synthesis_prompt.txt` | research | 给 LLM 的提示(含「只能引用指标卡数字」硬约束) |
| `{code}_final.md` | synthesize | 渲染三段定性后的最终报告 |
| `{code}_lint.json` | synthesize | Number Lint `{scanned,matched,ignored,passed,issues[]}` |
| `{code}_synthesis.json` | synthesize | LLM 三段定性(= Opinion) |

| `number_lint.py` | 防幻觉数字机检(见下) |

### 5.7 两层防幻觉

1. **Number Lint**(`number_lint.py`):扫描报告正文,把「不是程序算出来的数字」报为 issue。
   - `(?<!\d)\d{6}(?!\d)(?!\.\d)` 掩码(**6 位股票代码不误判**);
   - `UNIT_SCALES` = 1 / 1e4 / 1e8 单位换算容差;
   - `TEMPLATE_CONSTANTS` 精确匹配;
   - 既往研报数字经 `--prior-metrics` 并入 known 集(让「较上次 +12%」不被误判为编造)。
2. **Quality Gate**(`quality_gate.py`):6 项机检,`gate` 命令输出。
   > 代码实际发 6 项;docstring 曾写 7 项(第 7 项 `no_hallucination` 已由 Number Lint 覆盖)——以**代码为准 = 6 项**。

> **已知技术债**:`_save_artifacts` 从不写 `report_fingerprint`,导致 `run_gate` 的可复现性检查恒短路通过。

## 8. 端到端数据流

### 8.1 日管线(9 步,cron 驱动)

```
migrate → collector(东财 7x24 快讯) → worker(AI 抽取 events) → cluster(语义去重 + 重审视 Pass)
→ quote-collector(涨停池,仅交易日) → entity-build(实体) → market-state(市场情绪)
→ daily-review(每日复盘) → reconcile(对账)
```

`scripts/pipeline.sh` 的**闸门**:
- **日期锚点取 GitHub `Date` 响应的 `Date` 头**(免疫宿主机时钟漂移),取不到才回退系统时钟并打显式 WARN;
- 周末跳过;早于 16:10(北京时间)跳过;当日 `pipeline-$TODAY.done` 已存在则跳过(防重跑);
- 任一步失败 → **记录不阻断**。

### 8.2 深研 run 状态机

```
pending → gathering → synthesizing → verifying → done | failed
```

- Go `internal/research/runner.go` 用 `os/exec python3` 调 CLI 三命令,**argv 数组不经 shell**;
- 触发入口两种,**共用一个镜像**:UI 按钮(`POST /api/v1/research-runs`)与 CLI(`./bin/research-run`);
- **危险点**:`runner.go` 的 argv 传参不得改成 `sh -c`,否则 `macro:cn_cpi` 的冒号有注入面。

### 8.3 截图导入两段式(交易 / 持仓 / 自选)

```
上传图 → /api/v1/trades/import(vision 抽取)→ 前端可编辑预览 → /api/v1/trades/confirm(确认入库)
```

- `kind ∈ {trade, position, watchlist}`;自选为**镜像语义**(服务端 diff `add`/`keep`/`remove`)。
- 预表格中**空字段 = 截图未拍到 → 确认时写 NULL,不写 0**(宁缺毋假)。
- 客户端降采样(`lib/image.ts`,长边 2000px,JPEG q0.85)以适配 10MB 上传上限。

### 8.4 个人回写(唯一写路径)

笔记 / 周报 / 交易 / 设置 / AI 对话全部经 `/api/v1` JSON 写接口
(`internal/web/api_write.go`);**无 vault、无 git 中间层**——落回 PostgreSQL 即为终点。

## 9. 部署拓扑

### 9.1 单镜像(2026-09-12 定,替代原 D-2 双镜像)

`Dockerfile` 三阶段:

1. `golang:1.26-alpine` 编译 → `/out/bin/`(`-s -w` 去符号表,-trimpath)
2. `node:20-alpine` 构建前端 → `dist/`
3. **`python:3.12-slim`** 最终阶段:nginx + Go bins + React dist + Python research 运行时

底座选 **debian 而非 alpine** 的原因:**Go 编排在 web 进程内直接 `os/exec python3`**,
故 UI「深研」按钮与 CLI 深研共用同一镜像。反向(nginx:alpine 上 apk add python3)需要
akshare/pandas 在 musl 上源码编译,不可行。

**代价**:web 容器多背 ~300MB research 依赖,且「改 Python 需重启 web」;
**换来**:UI 触发零 Go 改动、无 docker.sock 安全面。

构建参数:`GOPROXY`(默认 `goproxy.cn`)· `APT_MIRROR`(默认 `mirrors.aliyun.com`)·
`PYPI_INDEX`(默认 pypi.org)· `GIT_SHORT` · `PIKS_VERSION`(默认 `v0.0.0`)。
镜像内烘焙 `PIKS_GIT_SHORT` + `PIKS_VERSION` 两个环境变量。

### 9.2 运行时组成

`configs/docker-compose.prod.yml` 三服务:

| 服务 | 说明 |
|---|---|
| `postgres` | :5433 **loopback** |
| `web` | 单镜像;命令 `./bin/web -listen 127.0.0.1:8090 & sleep 1; exec nginx`;发布 :80 → **:8090** |
| `tools` | `profile=run`,user `1000:1000`,跑管线命令 |

环境:`TZ=Asia/Shanghai`;`SSL_CERT_DIR=/etc/ssl/certs:/certs`(自签 AI 网关 CA);
卷 `piks_data` + `./certs:ro`。

### 9.3 nginx(`configs/nginx.conf`)

单 server :80;`client_max_body_size 10m`;gzip;`/api/` → `proxy_pass http://127.0.0.1:8090`;
`/` → `try_files … /index.html`(SPA fallback)。

### 9.4 部署流程(`scripts/deploy.sh`)

```
VER="$(git describe --tags --exact-match || echo v0.0.0)"
IMAGE_TAG="${VER}-${GS}"          # 版本 + 短 hash,缺一不可
build → docker save | ssh lab docker load → scp compose → postgres up → migrate → web up
```

- **未发版恒 `v0.0.0`**;正式发版才在 master 打语义 tag。
- 每次部署**保留回滚镜像** `<name>:rollback-pre-<阶段>`。
- lab(192.168.0.202)**不保留代码仓库,镜像 = 唯一交付物**,编排全在 dev 侧。

## 12. 边界(明确不做)

- **不自动交易 / 不荐股 / 不发买卖信号 / 不接资金 / 不做高频行情**。
  交易功能只做「记录 + 解读 + 诊断」——不连券商、不下单、不做信号。

- 不上:队列框架 / Elasticsearch / Neo4j / Kubernetes / 微服务 / 多 AI Agent / 十几个数据源。
  任务调度 = cron + PG 任务表。
