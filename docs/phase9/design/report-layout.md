# 研报体裁与版面（专业报告呈现层）

> 状态：**提案（待定稿门）**，2026-09-16。经用户过目后定稿，此后按它执行、改动走变更。
> 阶段定位：呈现层体裁重构 —— 把「研报」从「个股深研 run 的仪表盘」中拆出来，成为独立体裁与独立版面。
> 关联 epic：公司研报 #11 / 行业研报 #12 / 宏观研报 #13；共同前置 = 主体轴泛化 #10。

## 1. 背景与问题

用户诉求（2026-09-16，原话）：

> 「这个研报考虑和个股分析在页面上拆出来，公司研报需要专业一点，排版格式都需要专业。」

### 1.1 现状：研报寄生在个股分析页里

`/research` 侧栏标签叫「研究报告」，但装的是**个股深研 run**（`complete-stock` / `short-term` 两个 profile，都吃 6 位股票代码）。报告页 `/research/:runId`（`frontend/src/pages/research.tsx`，130 行）是**运维仪表盘**形态，固定四段：

| 段 | 组件 | 手写序号位置 |
|---|---|---|
| 一、事实（机器算的） | `FactSection.tsx:21` | 组件内 |
| 二、AI 研判（仅供参考） | `OpinionSection.tsx:26` | 组件内 |
| 三、数字机检详情 | `GatePanel.tsx:37` | 组件内 |
| 四、报告正文 | `research.tsx:117` | 页面内 |

问题：

1. **序号散落 4 个文件**，靠人工对齐；章节增删必然错位。
2. **`GatePanel`（机检详情）是运维面板**，不是研报内容 —— 夹在一「事实」与「正文」之间，专业读者看到的是管线内部。
3. **正文置底**：`research/src/report/markdown.py:128` 把 `{{ai_synthesis}}` 槽位追加在**免责声明之后**，即执行摘要排在文档末尾。研报必须摘要前置。
4. **内容重复**：AI 三段定性既被渲染进 markdown 末尾（`{{ai_synthesis}}`），又被 `OpinionSection` 在页面上单独渲染一次。
5. `ReportHeader.tsx:53` 硬编码 `<Link to={/stock/${code}}>` —— 任何非股票主体点进去必 404。

### 1.2 为什么不能在 `/research` 里原地改

#11 公司研报、#12 行业研报、#13 宏观研报**共用同一套体裁**（封面头 / 章节编号 / 专业表格 / 三域标记 / 免责声明），但**都不是个股分析**：

- 行业研报的主体是行业指数（`sw801010`），无持仓、无龙虎榜、无「买哪只」结论；
- 公司研报是**文档体裁**（专业、成篇），与「个股分析」（行情/量价/持仓视角的速览）职责不同；
- 宏观研报连标的代码都没有。

「专业版面」因此不是 #12 的前端细节，而是 **#11/#12/#13 的共同前置**。若塞进 #12，会在 #11 里重做一遍。

### 1.3 决策：先定版面，再写代码

用户明确选择「先定版面再写代码」。本文档即该定稿门产物。**本文档通过前，不写任何前端/后端代码。**

## 3. 关键决策（D-R）

| 编号 | 决策 | 理由 |
|---|---|---|
| **D-R1** | 研报是**独立体裁**，独立侧栏入口 `/reports`；`/research` 保留并改标签为「个股分析」 | 职责不同：研报=成篇文档，个股分析=行情/量价/持仓速览。#11/#13 直接挂 `/reports` |
| **D-R2** | 行业/公司/宏观**共用一套版面**，差异只由 `subject_type` + 章节清单驱动 | 「专业」= 一套一致的体裁规范，不是三套各写各的 |
| **D-R3** | 主体表示：行业 `sw\d{6}` / 公司 `\d{6}` / 宏观 `macro:<key>`（预留） | `NormalizeCode` 对 `sw801010` **原样穿过**（实测，要求 `len==前缀+6`），且 `IsStockCode` 判 false → 股票逻辑天然忽略，零冲突 |
| **D-R4** | 版面形态：**单栏正文（约 720px）+ 左侧固定目录** | 用户选定。券商研报标准形态，长报告可导航 |
| **D-R5** | **三域标记**：数据（Fact）/ 计算（Observation）/ 研判（Opinion） | 用户选定。「专业」的实质来源 —— 读者能区分硬数据与 AI 叙述，契合项目 Fact ≠ Inference 取向 |
| **D-R6** | **摘要前置**：改 `markdown.py` 装配顺序，执行摘要置于正文之首、免责声明置尾 | 当前摘要排在文档末尾，是研报体裁的硬伤 |
| **D-R7** | 无预测口径落到版面：估值只做**横截面排名**，禁止「估值历史分位」表述 | 实测：申万行业 PE/PB **只有当期快照**（`sw_index_*_info`），无历史序列。写「PE 处近 5 年 12% 分位」= 编数字 = Number Lint 必挂。详见 §4.4 |
| **D-R8** | 目录与三域标记由**章节清单**驱动，清单落在 `metrics.meta.section_manifest`（JSONB，**零 schema**） | TOC 需知道章节与域；`MarkdownBody` 是裸 `react-markdown`+`remark-gfm`，无 heading id、无锚点，加 `rehype-slug` = 引入插件。用清单则零新增依赖、零后端迁移 |
| **D-R9** | 机检/管线信息**移出正文**，降为封面头的徽标 + 可展开的次要面板 | 专业读者要的是报告，不是管线状态；但「机检未过」必须仍可见（诚实原则） |

## 4. 版面规格

### 4.1 整体骨架

```
┌──────────────────── 封面头（.report-cover）─────────────────────┐
│  白酒Ⅲ  (851251.SI)                    [行业研报]               │
│  申万三级 · 成分 19 只 · 数据截至 2026-09-14                     │
│  [偏负面] [数字 42/42 可溯源] [机检 通过 ▾]                       │
└──────────────────────────────────────────────────────────────┘
┌─── 目录 ───┬──────────── 正文（.report-body, ~720px）──────────┐
│ 一 执行摘要  │  一、执行摘要                        [研判]        │
│ 二 行业行情  │  …（AI 三段定性的 summary）                       │
│ 三 估值定位  │                                                 │
│ 四 成分结构  │  二、行业行情                        [数据][计算]  │
│ 五 风险提示  │  ┌──────────────────────────┐                  │
│ 六 数据说明  │  │ 指标        数值          │  ← .table        │
│             │  └──────────────────────────┘                  │
│             │  点位分位 88 · 回撤 −12.4% · 年化波动 31.2%      │
│             │                                                 │
│             │  三、估值定位                        [数据]       │
│             │  当前 PE(TTM) 25.7（横截面 31 行业中第 26）      │
│             │  …                                              │
└─────────────┴─────────────────────────────────────────────────┘
   免责声明（.report-foot）
```

### 4.2 封面头（`.report-cover`）

单张 `.panel`，行结构：

| 行 | 内容 | 类 |
|---|---|---|
| 1 | 主体名 + 主体码（等宽） + 报告类型 chip | `h1` + `.num` + `.type-tag` |
| 2 | 副信息：层级 · 成分数 · 数据截至 · 期间 | `.report-cover .sub`（`.num`） |
| 3 | 结论 chip + **可溯源计数** + 机检徽标（可展开） | `.st` 系 + `.report-checks` |

- 「数字 N/N 可溯源」= Number Lint 的 `matched/scanned`，**正面呈现**而非埋在机检面板里 —— 这是研报专业性的直接凭据。
- 机检详情（原 `GatePanel`）收进 `.report-checks` 折叠区（默认收起），**保留**而非删除。
- 报告类型 chip 文案：`行业研报` / `公司研报` / `宏观研报`（由 `subject_type` 决定）。

### 4.3 三域标记（D-R5）

每个章节标题右侧带域标签：

| 域 | 标签 | 含义 | 数据来源 |
|---|---|---|---|
| **Fact** | `数据` | 可溯源到当前指标卡的硬数据 | `{code}_metrics.json` |
| **Observation** | `计算` | 程序确定性计算出的派生量（分位/回撤/排名/中位） | 派生自 metrics，规则确定 |
| **Opinion** | `研判` | AI 生成的定性叙述 | `synthesis` JSON |

- 域标签复用 `.st` 系徽标，**不新增颜色**：`数据`= `.st-dim`、`计算`= `.st-accent`、`研判`= `.st-amber`。
- 域由 `section_manifest` 声明（D-R8），不由标题正文猜测。
- 章节可带多域（如「行业行情」= `[数据][计算]`）。

### 4.4 章节结构（以行业研报为例）

| 序号 | 章节 | 域 | 内容 |
|---|---|---|---|
| 一 | 执行摘要 | 研判 | AI 三段之 summary |
| 二 | 行业行情 | 数据 + 计算 | 指数点位、区间涨跌、**点位历史分位**、最大回撤、年化波动 |
| 三 | 估值定位 | 数据 | 当前 PE(TTM)/PB/股息率 + **横截面排名**（31 个行业中的位次） |
| 四 | 成分结构 | 数据 + 计算 | 成分股数量、ROE / 净利增速 / 营收增速的**中位与四分位** |
| 五 | 风险提示 | 研判 | 确定性风险清单 + AI 叙述（不预测） |
| 六 | 数据说明与免责声明 | — | 数据源、口径、生成时间、免责 |

**D-R7 的版面体现（关键）**：

- 二章可写：「当前点位处于 1999 年以来 **88% 分位**」—— `index_hist_sw` 给了 6455 个交易日、26 年 9 个月的序列，**可溯源**。
- 三章**只能**写：「当前 PE(TTM) 25.7，31 个申万一级行业中**排名第 26**」—— 横截面快照，**可溯源**。
- 三章**禁止**写：「估值处于近 5 年 12% 分位」—— 该序列**数据源不提供**，写了即编造，Number Lint 会拦（`lint_text` 只认当前指标卡）。

> 行业研报的 `synthesis` 硬约束须在 `synthesis.py:70` 的四条之外**追加一条**：
> 「不得表述行业估值的历史分位；估值只可作横截面比较。」

### 4.5 表格规范

- 一律原生 `<table class="table">`（既有约定，无表格库）。
- 数字列：`.num`（等宽 + tabular-nums + 右对齐，强制规则 2）；行高 44–52px。
- 涨跌用 `.chg.up/.down`，**A 股习惯**（涨红跌绿，强制规则 1）。
- 表格不加卡片外壳（`.panel`）—— 研报正文里表格直接嵌入 prose 流，靠 `.prose-piks table` 既有边框规则。

### 4.6 页脚（`.report-foot`）

数据源、复权口径、生成时间、免责声明。与正文视觉分离（上边框 + `--ink-faint`）。

### 4.7 目录（`.report-toc`）

- 左侧固定，宽约 200px，`position: sticky`。
- 数据源 = `metrics.meta.section_manifest`（D-R8），**不解析 markdown 标题**（无锚点、不可靠）。
- 当前章节高亮：`IntersectionObserver` 监听正文中章节锚点。
- 锚点 id 由前端按章节序号生成（`sec-1`、`sec-2`…），**不需要 markdown 插件**。
- 窄屏（< 960px）目录折叠到封面头下方为横向 chip 行（复用既有响应式断点）。

### 4.8 章节清单契约（`metrics.meta.section_manifest`）

零 schema，写入 `metrics` JSONB：

```json
{
  "meta": {
    "section_manifest": [
      { "title": "执行摘要", "domains": ["opinion"] },
      { "title": "行业行情", "domains": ["fact", "calc"] },
      { "title": "估值定位", "domains": ["fact"] },
      { "title": "成分结构", "domains": ["fact", "calc"] },
      { "title": "风险提示", "domains": ["opinion"] },
      { "title": "数据说明与免责声明", "domains": [] }
    ]
  }
}
```

- 由 research 侧 `json_report.py` 产出（它已知道 `sections`），**不升 contract**（新增字段不升，符合 `research/README.md` 契约规则）。
- Go 侧不解析、不校验，原样透传（前端消费）。
- 旧报告无此字段 → 前端回退到「解析 `## ` 标题、域留空」的降级路径（零回归）。

## 5. 设计令牌与复用

> 约束（CLAUDE.md）：**Tailwind 只做布局**（flex/grid/gap/px）；**视觉一律走 `globals.css` 语义类**。

### 5.1 直接复用（不新增）

`.panel` `.panel-pad` `.table` `.num` `.num-t` `.st`（`.st-accent/-up/-down/-amber/-dim`）`.type-tag` `.t-*` `.chg`（`.up/.down`）`.prose-piks` `.day-title` `.page-head` `.chip` `.chip-btn` `.filter-bar` `.footer`

### 5.2 新增语义类（写入 `globals.css`，走 `:root` token）

| 类 | 用途 | 依据 token |
|---|---|---|
| `.report-cover` | 封面头容器（含 `.sub`） | `--card` / `--line` / `--radius-card` |
| `.report-toc` | 左侧目录（含 `.on` 当前项） | `--muted` / `--accent` |

### 5.3 `.prose-piks` 补全

现状**缺** `h1` / `a` / `h4-h6` / `pre` 规则，链接样式在调用点 ad hoc。本设计补：

- `.report-body h1`（封面头已承载标题，正文 h1 仅兜底）
- `.prose-piks a`（accent + 下划线，hover 加深）
- 段落行宽：`.report-body .prose-piks` 限 `max-width: 68ch`（可读性）
